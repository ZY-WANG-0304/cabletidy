# 凭据保护

CableTidy 可在代理发送前，将模型上下文中的真实凭据 A 替换为随机占位符 B；收到响应后，把当前会话已知的 B 还原为 A。客户端和本地审计仍看到原文 A。审计与保护共享同一份原文候选检测结果（候选 ID、证据、角色与字节位置），分别决定告警与保护动作。保护关闭时检测和审计仍运行；保护无法安全执行时拒绝转发。

## 开启与配置

在管理台“设置 → 凭据保护”统一管理所有线路。“启用凭据保护”是总开关：只有总开关开启且线路选中时，才执行凭据替换与响应还原；总开关关闭时所有线路均不执行保护，即使线路已选中。开启后可通过独立的“全选线路”复选框全选或全部取消，也可逐条调整；部分线路选中时，全选框显示部分选中状态。关闭时全选与线路选项禁用，原有选择保留；重新开启恢复原有选择。全局开关、线路选择与映射闲置有效期通过同一个“保存设置”按钮一起保存，立即用于后续请求，刷新或重启后保留选择。新配置的总开关默认关闭，新增线路默认选中，受总开关控制。线路详情页不再单独提供保护设置。

```json
{
  "credentialProtection": {
    "enabled": true,
    "mappingTtlSeconds": 3600
  },
  "virtualProviders": {
    "cabletidy_relay": {
      "credentialProtection": true
    }
  }
}
```

全局 `mappingTtlSeconds` 是会话闲置有效期，默认 3600 秒，可设为 60 秒到 30 天的整数秒。全局 `enabled` 控制是否执行保护，线路 `credentialProtection` 表示是否选中；线路字段缺失时默认选中。设置页保存时将每条线路的选择写入布尔值，线路导入导出保留此选择。已有配置格式无需迁移，但旧配置中“全局关闭、线路启用”现在也受总开关限制，不执行保护。共用同一 Virtual Provider 入口的线路共用保护状态，调整其中一条会同步其他共用线路。

“配置保护线路”右侧显示已选数量，线路名称为主要信息，客户端类型为辅助信息；重名线路附加 ID 以区分。“会话闲置有效期”默认显示 1 小时，支持秒、分钟、小时、天，切换单位时换算数值，保存时统一换算为整数秒。“保护范围说明”默认折叠。

同一入口、协议和会话中的相同 A 使用相同 B。每个新请求重置会话倒计时，包括没有新凭据的请求；超过 1 小时没有请求时，默认映射过期。请求头标识在接收请求时续期，仅正文提供的会话标识在完整解析后续期。过期后的新请求建立新的 B；仍在执行的旧请求保留其映射用于响应还原。进程重启清空运行时映射。

会话身份复用现有审计归组：Codex 会话头、Claude Code 会话头和 `metadata` 会话标识；按入口与协议隔离。没有可识别会话标识时按单条请求隔离。会话标识是客户端报告，不能作为多租户身份认证。此前会话的实时映射也可用于还原 `previous_response_id` 等服务端历史引用产生的响应；映射已过期或重启后，不会从审计数据库重新激活映射。

## 处理范围

识别本地已保存凭据、常见 API Key、GitHub Token、AWS `AKIA`/`ASIA`、私钥，以及实际凭据字段、明确赋值字面量、Bearer/Basic、URL 认证参数和会话 Cookie 中的凭据。检测器先收集证据，再冻结强凭据目录，统一生成原文范围；替换器只执行这些范围，出站校验核对计划输出的完整字节和 JSON 有效性，不在修改后的正文重新发现候选。

源码使用有界字段预筛与字面量读取，排除代码变量、成员表达式、函数调用、类型声明、比较、正则、动态拼接/插值、Markdown 字段标签与 `[REDACTED]` 等明确遮罩。完整单/双引号和固定反引号字面量可保护；可靠解码的源码值用于会话检测，替换定位与响应还原仍保留源码原始拼写。未知转义和未闭合字面量只作低置信审计，不自动替换或学习。普通 Cookie 偏好（如 `theme=dark`）保持原文，认证 scheme、字段名和分隔符保持有效。无认证上下文的 JWT 外形作为低置信审计候选，不自动替换或学习；有认证上下文时保护实际值，不联网验证活性。实际密码 `test`、`changeme`、短值和低熵值不能仅凭词语被免检。

后续请求复用有版本与来源的同会话映射，匹配策略实际参与检测：自发现的短值和低熵纯单词只匹配完整值；较长自发现值按凭据单位边界匹配，不截取代码标识符内部的子串；本地登记值可以在正文中匹配精确拼写。普通正文中的 `plain` 与 `plain_source` 不会因短值映射被修改。旧规则版本的映射只能用于响应还原，不再作为新检测依据。服务器地址仅审计，不替换。

工具 grammar/format、协议标识和引用、Schema 的 `pattern`、`const`、`enum` 等约束属于不可安全改写结构。真实强凭据出现在其中时返回 `422 credential_protection_failed`，说明结构内凭据无法安全替换，不将原值发送给上游。Schema 的普通定义元数据保持原文，实际 credential `default`/`example` 可保护。内嵌 JSON 逐个扫描原始成员，重复键分别定位；外层凭据字段语义保留到内部值，数字和布尔凭据拒绝转发，JSON `null` 保留，字符串 `"null"` 仍按实际值处理。

结构字段、普通赋值和 URL 查询字段共用凭据名称表，按分隔符及大小写词元边界识别 `dbPassword`、`DATABASE_PASSWORD` 等后缀；`notapassword`、`password_policy`、`secretRef` 等非值名称不因此命中。支持的名称包括 `AWS_SECRET_ACCESS_KEY`、`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`X_AUTH_TOKEN`、`id_token` 等；因此首次出现在 `.env` 工具输出中的凭据也会保护。查询按解码后的键对值应用凭据语义。Schema 每个新的 `properties` 子属性重新判断是否为凭据定义，认证对象中的普通 `enabled`、`encoding` 等默认值、枚举和示例保持原义。

B 格式为 `CTSEC_v1_` 加 32 位小写十六进制随机 UUID，共 40 个 ASCII 字符，不含 A 的片段或散列。只有完整符合此格式的值才按占位符处理，单纯以此前缀开头的真实凭据仍保护；本地已保存或同会话已学习的真实凭据优先保护，即使其格式恰好与 B 相同。凭据字段与赋值、Bearer、URL 认证文本采用相同的完整占位符检查，已有 B 不会再次学成新 A；同会话已知 B 保留原映射还原，未知 B 和其他会话的 B 保持字面值，不读取任何 A。只还原本次请求持有的同会话映射。

支持 Responses 与 Messages 的 JSON 请求、普通 JSON 响应、UTF-8 文本错误响应、工具参数中的嵌套 JSON，以及常见 SSE 文本、拒绝和工具参数事件。SSE 普通文本按独立通道暂存可能属于 B 的尾部，跨片段完整匹配后还原；以 `{` 或 `[` 开头（忽略前导空白）的文本按通道收齐，再按完整 JSON 字符串层级还原，避免分片改变引号和反斜杠的转义；普通前缀碰撞（例如结尾的 `C`）在通道结束时原样释放。流式 JSON 工具参数按调用收齐，在对应工具或响应结束前验证完整 JSON、按实际嵌套字符串层级还原，再补发参数增量；因此开启保护时工具参数和上述 JSON 文本需等待通道结束，普通文本仍按增量返回。标准 SSE 的事件名、ID 和注释与数据保持在同一事件。内嵌 JSON 按解析后的字符串匹配，支持 Unicode 转义和代理对，保留本地审计中的原始拼写。JSON 字符串嵌套处理最多 4 层，超出时拒绝转发；不能承诺识别任意编码、二进制、图像、加密内容或模型改写后的 B。

Claude `content_block_start.text` 与 Responses 初始内容／摘要 part 也参与所属通道的匹配、JSON 判断和结束校验，B 跨初始事件与后续 delta 时仍完整还原。初始事件中尚不能安全输出的尾部暂存，结束时通过对应 delta 补发，不重复发送 start 事件或已发出的内容。通道只接管正文节点，同一容器中的引用、注释等其他非不透明字段仍按完整 B 还原，各处实际操作分别计数。

签名、思考和加密字段不修改。若请求在这些字段或对象键中含已识别的 A，或者凭据字段不是字符串且无法安全替换，发送前返回 `422 credential_protection_failed`。思考和签名通道也跨事件累计检查，保留原文。若响应的签名或不透明字段含需要还原的 B、流式占位符不完整、响应无效或资源不足，终止响应并记录还原失败。保护失败不会回退到发送明文 A。

附加请求头、最终上游 URL、查询参数、选定模型名也检查凭据，包括常见百分号编码。查询参数按 form-urlencoded 语义分别解码键和值，`+` 表示空格、`%2B` 表示字面加号；请求头不采用此空格规则。存在需要保护的凭据、百分号编码超过检查层数，或附加请求头（包括 `Accept`）无法解码检查时，拒绝转发这些参数。上游 HTTP 身份认证仍使用真实 API Key，这是连接上游所必需的认证，不属于模型上下文替换。SSE 的 `data: [DONE]` 会先结束并校验所有还原通道，再原样传递结束标记。

## 管理台与审计

会话轨迹概览的色块在发生实际替换或还原时显示小钥匙。详情页签顺序为：概览、风险、凭据保护、请求内容、响应内容、原始内容。

“凭据保护”摘要分别统计涉及的不同凭据数、请求替换次数和响应还原次数，并展示候选总量、低置信候选数和未替换原因。分页 `credential-detection` 原文证据快照记录检测事实、`source`、`credentialType`、`valueType`、实际目录 `matchPolicy` 与审计策略版本；`protection` 快照中的决策引用相同候选 ID，独立记录保护策略版本、`replaced` / `not_replaced`、未替换原因与 `forwarded`。只有实际执行且通过校验的位置才记为已替换；未替换时分别记录策略未选择、保护关闭、结构不可修改或执行失败等原因，置信度不能覆盖实际状态。旧记录或缺失证据显示“未记录”，不将未知当作未替换。本次保护列表每个原文 A 一条，提供原文预览与复制、新建 / 复用标记、两侧操作次数；本次未使用的会话映射放在摘要下方，默认折叠。每条凭据的“映射详情”默认折叠，展开可查看 B、创建时间与本次请求续期后的到期时间。到期时间是当时的证据时间，不是整个会话当前的实时倒计时；后续请求会继续续期。

风险页按同一候选事实说明本地已知凭据、明确凭据值上下文、支持格式／私钥封装或未确认候选，并展示实际已记录的替换状态。强证据对应凭据告警、低置信度对应候选提示；“高置信度”仅说明离线证据，不表示已经验证凭据活性。当前检测版本为 `credentials-4`，审计策略为 `audit-4`，保护策略为 `protection-2`。规则升级后，旧版本映射仅用于同会话还原，不再成为新请求的检测或替换依据；新请求的强凭据重新判定并生成当前版本映射。历史审计的规则版本、置信度和结论保留原样，计算缓存按新版本失效。

“请求原文（X 处）”“响应原文（Y 处）”在对应次数大于 0 时显示，当前采用弹出框试用定位：按审计保留的保护位置展示原文上下文、命中位置及当前 / 总数，支持上一处、下一处；完整内容仍通过原有页签查看。工具参数、附加字段和重组的流式响应位置也可定位。操作次数与可定位原文数量可能因保留缺口而不同，弹出框会明确说明。

页面分别提示未启用、已启用但本次 0 次操作、保护失败和保护证据不可用。证据不完整时，不会用 0 个凭据或 0 次操作表示未知结果。

请求、响应和原始内容展示 A。仅风险命中使用浅黄色背景，仅保护使用浅青绿色背景；同时命中时上半部浅黄色、下半部浅青绿色，并加青绿色底线，换行后每行保持相同样式。点击定位时叠加橙色外框。响应正文注明“还原后客户端响应正文”。普通 JSON 的高亮依据替换路径与偏移，流式原始正文保留指向重组内容快照的引用，关联流式内容显示 A 及保护标记。响应中原本存在的 A 不因另一处 B 被还原而自动标为已保护。

次数统计实际传输内容中的替换操作；SSE 的增量、done 事件和最终对象重复携带 B 时，各次还原分别计数，不代表不同凭据数量。只有发生操作才显示钥匙，开启但没有命中的请求不显示。

运行时映射仅驻留内存，受全局工作内存预算约束，闲置到期后不可复用并由后台回收；活跃请求保有的引用在结束后释放。暂存正文使用现有加密 Spool 和全局预算。完整 A↔B 证据作为分页正文快照存入本地审计库，跟随审计保留周期和容量清理，因此运行时过期或重启后历史仍可查看。审计数据库保留明文 A，应按现有本地原文审计要求管理；没有另存一套含 B 的实际传输正文。审计存储不足时明确标记证据不可用。

## 验证

自动测试覆盖审计/保护同快照候选复用、保护关闭继续审计、源码误报与会话污染、grammar/schema 强凭据拒绝、原始/解码位置、实际操作状态，以及同会话复用、并发一致性、闲置续期与过期、活跃旧请求还原、跨会话与未知占位符隔离、跨片段 SSE、Claude 交错文本和工具参数、嵌套引号/反斜杠/中文、失败前不联系上游，以及重启后的原文和高亮。浏览器验收覆盖桌面和手机上的设置、图标、六个页签、定位与原文展示。

第三阶段补充受限 `string` / `str` / `&str` / `String` 类型注解后的凭据字面量，以及 `session_token` / `sessionToken` Cookie；不求值动态表达式。分层语料、原始留出失败与性能报告见 [第三阶段验收记录](research/credential-protection-v2/stage3-report.md)。工程回归通过；合成样本独立性及保护开关 p95 门槛仍未全面达标，不据此宣称生产精确率／召回率或延迟承诺。
