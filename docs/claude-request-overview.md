# Claude Code 请求内容概览

## 调研结论

Claude Code 通过本项目的 Anthropic Messages 接入发送模型上下文。一次请求可能包含系统提示词、多条用户与模型消息、思考块、工具调用、工具结果和工具定义。概览必须解析整个请求，不能只取最近一条用户文本。

Messages 与 Responses 的关键区别是内容块的归属。系统提示词使用顶层 `system`，它可以是字符串或文本块数组；`messages` 没有 `system` 角色。每条消息的 `content` 可以是字符串或内容块数组。`assistant` 消息可以同时包含文本、思考和多个 `tool_use`；客户端把 `tool_result` 放在后续 `user` 消息内，也可以同时追加用户文本或图片。因此，工具结果必须按块识别，不能因为父消息是 `user` 就计为用户输入。

`tool_use.id` 与 `tool_result.tool_use_id` 对应；工具参数是结构化 `input`，结果可以是字符串、多模态内容块或缺省内容，`is_error` 是客户端报告的错误标志。`tools` 是可用工具定义，不表示发生过调用。服务端工具使用 `server_tool_use` 和对应的 `*_tool_result`，也不能计为普通模型文本。

`thinking.thinking` 是可读思考内容，`signature` 是验证签名；`redacted_thinking.data` 是不透明加密数据。官方要求思考块按原顺序、原内容传回。`cache_control` 是缓存控制元数据，不属于提示词文本。概览读取留存副本，不改变这些字段或代理请求。

官方依据（2026-10-09 查阅）：

- [Messages API](https://platform.claude.com/docs/en/api/messages)：`system`、消息内容块、工具 ID、错误标志、多模态内容、思考签名、服务端工具与缓存字段。
- [工具调用实现指南](https://platform.claude.com/docs/en/agents-and-tools/tool-use/implement-tool-use)：工具定义、调用与客户端返回结果的完整交互。
- [处理工具调用](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handling-tool-calls)：工具结果的消息归属、顺序和并行调用。

## 请求内容页签

| 请求结构 | 展示方式 |
| --- | --- |
| `system` 字符串或每个文本块 | 系统提示词，单独展示缓存控制 |
| `messages[i].content` 字符串 | 一条用户输入或历史模型消息 |
| 文本、图片、文档、检索结果块 | 按块和父消息角色计数；非文本类型标示并提供原文入口 |
| `tool_use` / `server_tool_use` | 历史工具调用、名称、完整 ID 与完整 JSON 参数 |
| `tool_result` / `*_tool_result` | 工具结果，与用户输入分开；对应调用、错误标志、多模态类型与缓存控制 |
| `thinking` / `redacted_thinking` | 可读思考或不透明内容标示；签名和加密数据通过原文查看 |
| `tool_reference` | 工具引用；嵌套于结果时标记该结果包含工具引用 |
| `tools` | 单独折叠的可用工具定义 |
| 未识别内容块 | 其他内容，完整保留结构与原文入口 |

右侧详情中的“请求内容”是独立页签，位于“风险”和“响应内容”之间，与“概览”“原始内容”同级。每项标明父消息序号、角色和块类型。概览按正文中的原始顺序编号；工具定义单独折叠。只有工具结果时，用户输入计数为零；空数组不补造消息。缺少调用或结果时明确提示，不按工具名猜测、不跨请求补造关联。重复 ID 提示关联歧义，长 ID 完整保留并参与匹配。

客户端报告的结果和 `is_error` 不证明宿主机的真实执行状态。服务端工具结果使用单独说明。图片和文档只展示类型标记与可读文本，不解码或推断其语义；不透明思考不尝试解密。缓存控制按记录值展示，不据此宣称发生了缓存命中。

## 读取与边界

Claude 与 [Codex 请求概览](codex-request-overview.md) 共用分页、只读的留存正文投影。每组最多 40 项，每项默认展开，完整展示文本与工具参数或结果，不设长度截断上限；计数涵盖全部已解析条目。工具定义展示完整 JSON；非文本载荷、思考签名及额外字段可在每项的“完整内容结构”中展开。单条消息包含大量内容块时仍可分页，工具关联支持跨页。正文逐段读取，只收集当前页内容，不保留整条消息历史；单项和本页的内存与返回大小随实际内容增长。请求列表保持轻量，详情返回首组，`GET /api/v1/security/audit/<id>/content?offset=40` 返回后续组。

解析在独立的只读线程执行，有界队列、30 秒等待上限及取消检查，避免阻塞审计查询和正文写入。首次扫描建立范围、角色和工具关联索引，缓存命中时后续翻页只读取选中内容块；缓存最多 8 份、按序列化元数据计 8 MiB，manifest 更新时失效，不缓存整份正文。

“查看此项原文”位于每项标题行右侧，收起时仍可使用；它使用保留正文的精确字节范围与结构位置，加载成功后滚动并聚焦到对应内容块的开始位置。导航位置与风险范围分开，不给整项内容新增风险高亮，已检测出的敏感内容仍保持原有高亮。旧格式正文快照和现有分段记录都可以生成概览，不需要重新发送请求或迁移写入。缺少正文时显示无法还原；正文中断时只显示已完成内容块。旧快照即使含有可解析正文，`truncated`、`partial`、`interrupted` 或缺少状态均显示不完整，不能以解析成功覆盖留存状态。JSON 字段顺序不影响完整消息的分类；若正文在角色到达前中断，已完成块归为其他内容并提示不完整，不猜测角色。

请求内容的解析完整性与安全检查覆盖是两个独立状态。包含图片或加密思考的完整 JSON 可以全部解析，但安全检查仍可能只覆盖部分内容。

## 验证

Rust 测试覆盖混合内容块、任意角色与类型字段顺序、系统字符串与数组、结构化工具参数、并行与服务端工具、错误和缓存字段、多模态结果、重复或过长 ID、空请求、单消息 105 个内容块分页以及中断正文。

HTTP 测试验证 Messages 转发载荷只发生配置要求的模型改名、跨页关联、原文字节定位、重启后已有记录和只读查询。页面测试验证分类、父消息角色、安全转义、元数据及原文入口。浏览器验收使用真实本地网关和模拟 Messages 上游，覆盖桌面及 390px 窄屏；这不等于对真实 Claude Code 版本或远端模型服务的兼容性验收。

桌面和 390px 窄屏另验证 120 KB 中文 / emoji 前置消息后的短内容块原文导航，确保正文和外层滚动区域都能看到目标，且没有新增风险高亮。
