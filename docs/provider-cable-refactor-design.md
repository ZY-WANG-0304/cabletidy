## 1. 目标与范围

**供应商管理模型供给事实；Cable 管理模型选择、客户端使用配置和提示词策略；客户端适配由代码实现。**

- 一条 Cable 对应一种客户端；同一种客户端可以创建多条 Cable。
- 一条 Cable 可以选择多个供应商，并显式勾选各供应商的部分模型。添加供应商、发现模型或同步目录都不会自动把全部模型加入 Cable。
- 供应商是服务实例，不限定类型；同一实例可以提供多个协议接口及不同类型的模型。新建时填写名称，通过接口和模型列表添加多项资源，确认后一次性创建；详情继续独立管理各项资源。
- 模型适配纳入本次重构：代码根据客户端及版本、接口协议、实际/参考模型身份或类型和能力，执行内置参数映射、工具转换、模型定义生成与历史处理规则。同一种已支持组合可用于多家供应商实例。不提供通用的用户自定义适配或映射编辑器。
- 保留模型能力表单，只要求用户填写少量直观的供给事实；输入类型、工具形式、推理控制与运行策略分开表达，配置选项完整保留，支持情况通过值与勾选状态表达；“推理”复选框控制“推理能力”区域的显示，档位和预算分区分别由对应控制方式勾选显示。页面默认值是填写起点，不代表真实测试通过。
- 原“适配预设”收紧为 **客户端提示词策略**：Codex Cable 选择本机原生模型的提示词；身份匹配时推荐对应提示词，未匹配时由用户选择。工具约定由代码校验，选择粒度遵守客户端实际机制。
- 首期已确认选择第 6.1 节的 A+B：Codex × Responses 下的原生 GPT 类型及指定的六个非原生目标模型。B 已扩展为一组模型，不再限定为一个非原生模型类型；按各模型身份和能力分别实现、验证，不假设六者共用同一适配规则。供应商实例数量不受此限制，验证接口后续确定；其他组合不属于首期验收要求。
- 供应商预设仅是预填配置的辅助，不是适配前提，不进入首期数据依赖、页面流程或验收。
- 跨协议转换、多供应商自动路由、负载均衡和故障切换属于本设计，按实现与验证结果逐项开放。基础阶段已支持一条 Cable 使用多家供应商；每个请求通过所选客户端模型确定来源，无需等待自动路由。

多条 Cable 的服务和配置独立保存。应用到同一份客户端配置时管理当前激活线路和共享字段；这不限制 Cable 的创建数量，也不影响其他线路的本地服务。

## 2. 调研依据与设计结论

| 调研结果 | 本设计采用的规则 |
| --- | --- |
| Codex 自定义模型名需要完整目录，目录提供指令、reasoning、上下文和工具元数据 [1] | 代码生成与客户端模型 ID 匹配的完整定义，模型改名不等于完成适配 |
| Claude Code、Gemini CLI、不同版本 OpenCode 的提示词和能力配置机制不同 [2][3][4] | 适配按客户端及版本实现；无法逐模型配置的字段不能伪装成逐模型生效 |
| Magpie 显式成员与目录匹配成员分开，并维护会话/工具回合亲和 [5] | Cable 使用显式模型选择；自动路由只在用户配置的候选来源内执行 |
| OpenCodex Combo 聚合能力和窗口，且对流式输出提交边界作判断 [6] | 多来源共享客户端模型时声明共同能力；故障切换不能拼接不同来源的回答 |
| Magpie 通过代码处理协议和模型差异；OpenCodex 维护能力及内置适配器，并提供有限配置映射 [5][6] | CableTidy 首期采用内置规则，用户配置集中在供给事实、模型选择和提示词策略，不建设通用适配平台 |

当前 CableTidy 的运行路径要求每条 Route 只有一个上游，模型设置主要属于 Virtual Provider。本次需要同时调整模型归属、请求选源和客户端配置生成，不能只修改页面的供应商选择框。

## 3. 数据归属与关系

| 对象 | 归属 | 核心内容 |
| --- | --- | --- |
| 供应商 | 全局管理 | 系统生成的稳定内部 ID、名称、启停状态；所属接口和供应商模型记录，不设供应商类型 |
| 接口 | 供应商内部 | 系统生成的稳定内部 ID、名称、协议、地址、内置认证方式与凭据引用、支持流式响应（默认开启）、支持响应 ID 续接（默认关闭）；多个接口可引用同一凭据 |
| 供应商模型记录 | 供应商内部 | 以“供应商 ID＋上游模型 ID”为唯一键，无独立内部记录 ID；实际/参考模型身份及版本或未知、可访问接口引用、能力和限制及必要的接口差异 |
| 客户端适配实现 | 代码维护 | 支持的客户端及版本、协议、模型类型组合；依据实际/参考模型身份与能力执行内置参数映射、工具转换、模型目录生成、历史处理，记录实现版本 |
| Codex 原生提示词 | 本机 Codex 版本目录 | 原生模型的完整指令、配套工具约定、生效范围、版本和内容摘要；CableTidy 不提供自写兼容提示词 |
| Cable | 线路管理 | 客户端类型、供应商引用列表、本地地址、模型绑定、默认模型、客户端提示词策略与启动设置 |
| Cable 模型绑定 | Cable 内部 | 唯一客户端模型 ID、显示名称、本版唯一来源；客户端默认推理档位、默认预算和按客户端机制开放的 `ultra` 使用配置；客户端支持逐模型策略时保存该模型的提示词选择 |
| 来源 | 模型绑定内部 | 供应商 ID、上游模型 ID 及可访问接口引用；本版不提供候选源选择、优先级或权重配置 |

接口、模型和候选来源是所属对象的内部记录，不单独增加管理模块。凭据集中保存，由接口引用，不复制到 Cable。适配实现和提示词模板不是用户可新增的业务对象；用户选择已有策略和可生效的客户端使用配置。客户端模型 ID、启动模型、推理默认值和提示词选择属于 Cable，用户的项目规则仍由客户端管理。

关系为：`客户端类型 → 多条 Cable → 每条 Cable 的多个供应商 → 显式选择的供应商模型记录`。一个供应商模型记录可被多个 Cable 复用。

### 3.1 供应商模型记录

- **上游模型 ID**：请求上游使用的标识，关联的协议接口共用此 ID；与供应商 ID 共同组成记录唯一键，不再生成独立的供应商模型内部 ID。
- **实际/参考模型身份**：填写实际模型，或用于参考能力和选择已实现适配的模型身份；不同版本通过不同身份 ID 区分，不设实际版本字段；身份依据另行保存。参考身份不等于供应商已确认提供该实际模型，无法确定实际或参考身份时留空。选择参考身份不会创建新的适配规则，也不会绕过当前组合的能力校验。
- **可访问接口**：引用供应商已配置的协议接口，表示该模型可通过哪些接口访问；候选来源只能选择其中的接口。
- **能力与限制**：维护这家服务的模型供给事实，包含输入类型、并行工具调用、是否支持推理及实际控制方式、上下文长度和最大输出长度；工具形式按模型通过具体接口分别声明。实际/参考模型身份用于选择适配，不代表部署环境的全部能力。客户端默认档位和默认预算不存入供应商模型。

不引入各接口独立的上游模型 ID。不同模型 ID 保存为不同供应商模型记录，即使对应同一实际模型；同一供应商内相同模型 ID 维护一条记录及其接口集合。

修改上游模型 ID 等同于移除旧记录、创建新记录，不迁移旧引用。新记录的可访问接口、能力事实及 Cable 选择需要重新配置和校验后生效。Cable 保留原客户端模型 ID 和旧的“供应商 ID＋上游模型 ID”引用，将相关绑定标为“来源不存在”；收到请求时返回明确错误，不自动替换或路由到其他模型。用户可显式重新绑定，之后重新校验适配、能力和历史兼容性。删除模型记录采用相同的失效语义。

### 3.2 模型列表与单来源绑定

每次添加供应商模型记录时建立独立 Cable 模型；客户端 ID 由 Cable 模型绑定管理，在 Cable 内唯一。初始 ID 由客户端适配器生成，允许用户修改，保存后保持稳定并符合客户端识别规则。自动显示名称默认包含供应商名称，改变显示名称或排序不改变 ID。

本版每个客户端模型 ID 只绑定一个来源，即一个“供应商＋上游模型 ID＋访问接口”。两个上游模型分别添加为两个客户端模型 ID，各自配置提示词、推理档位及默认模型选择；即使实际身份或上游模型名相同，也不合并。相同规则适用于同一供应商的两个模型和不同供应商的模型。

例如供应商 A 与 B 均提供某模型，在线路中添加 `model-a` 与 `model-b`，客户端看到两个独立选项；一条线路仍可使用多家供应商。同一上游来源也可显式建立不同客户端模型 ID，以使用不同配置。

本版不提供单个客户端模型的来源列表、来源合并、手动切换、优先级或权重配置。替换绑定的唯一来源属于编辑模型，需重新校验使用配置、适配与历史兼容性；目录或提示词变化后重新应用，历史不兼容时使用新会话。

已有多来源配置不得在升级或普通保存时静默丢弃来源。建议保留原记录并提示需要拆分，由用户显式确认转换为多个单来源绑定；转换方案须保留原客户端 ID 对应的当前来源，其余来源生成新 ID，并重新校验各自使用配置。此兼容转换细节待实施前核对实际数据，不作为继续开放多来源编辑的理由。

选择一个供应商只把其模型列为候选，不勾选任何模型。来源必须属于 Cable 已选择的供应商；移除供应商时列出受影响绑定，由用户明确移除或替换来源。绑定无来源时保留为待配置，不自动补入其他模型。

## 4. 供给事实、代码适配与提示词策略

分别判断 **实际/参考模型身份、客户端原生支持、协议兼容、适配实现状态、验证状态**。原生支持是模型与客户端及版本的关系，不是供应商整体属性；同一供应商可同时提供原生和非原生模型。

### 4.1 供应商声明能力事实

能力描述的是“这家供应商通过该接口提供的模型能力”，可能受到部署与接口实现影响。表单以直接可理解的输入类型和能力复选框声明供给，保留必要的未知事实；不把所有项目统一做成三态下拉框。默认勾选与实际验证结果分开。

**输入类型与并行工具调用：**

- 输入类型单独成组，常见类型为文本、图片、音频、视频；具体显示和可用项遵守实际已支持范围。模型公共值可复用，有接口差异时在对应接口下记录。
- 文件上传属于服务输入方式，不能从“可以上传文件”推断模型支持图片、音频或视频，也不能从实际/参考模型身份推断部署暴露全部模态。
- 保留“并行工具调用”复选框，表示模型一次响应可以产生多个工具调用。未知模型新建时默认勾选，用户可取消；编辑已有记录时保留原选择，不重新套用默认值。默认不代表已实测，客户端是否同时执行工具属于另一项运行策略。
- 上下文长度和最大输出长度属于供给限制，使用第 5.1 节的长度输入组件，保存准确整数 token；未知时留空。

传输、服务端状态和模型工具能力分开归属：

| 配置 | 数据归属与默认值 | 运行约束 |
| --- | --- | --- |
| 支持流式响应 | 接口 `supportsStreaming`，默认开启 | 默认不表示已实测；模型通过接口的流式例外仅在有差异时记录，不能绕过接口不支持的声明 |
| 支持响应 ID 续接 | 接口 `supportsResponseIdContinuation`，默认关闭 | 这是服务端状态能力，完整历史与续接可以同时存在；实际使用由客户端适配代码决定 |
| 支持的工具形式 | 模型 `interfaceCapabilities[接口 ID].toolForms` | 显式选择 `function`（JSON 函数工具）、`custom`（文本输入工具）；新建模型或新增 Responses 接口关联时默认勾选 function 和 custom，其他协议默认只选 function；默认值表示接入预期而非已实测。编辑保留已有声明（包括空数组），空数组表示不支持工具调用；身份参考填充不修改工具形式 |
| 实际历史处理 | 客户端适配代码 | 无用户策略字段或编辑入口；首期 B 固定完整、无状态历史，即使接口勾选续接仍拒绝远端历史引用 |

模型与接口关联使用两个独立折叠区：“模型在此接口下的能力”和“此模型支持的接口能力”，不再套入“接口名 · 能力与限制差异”外层折叠区。前者默认继承模型公共输入类型、推理能力、并行工具调用、长度及预算限制，后者默认继承接口流式响应等功能。关联只能收紧：能力和输入类型、推理控制方式及档位必须是模型公共声明的子集；长度不得超过已知公共上限，最小预算不得低于公共下限、最大预算不得超过公共上限，预算单位一致。接口未支持的功能不得开启。上层限制未知时允许记录数值限制，但不据此补充布尔能力、输入类型或推理档位。

两个折叠区分别提供“恢复模型默认”和“恢复接口默认”。折叠时仅显示简短提示：模型区按是否存在显式限制显示“继承模型本身配置，可单独收紧”或“已单独收紧模型能力”，接口区显示“继承接口配置，可单独限制”或“已单独限制接口功能”；展开后隐藏折叠提示，不罗列能力或数值。所有配置项保留，上层未支持的选项保持未勾选，鼠标或键盘尝试开启时弹出原因提示且不改变声明。长度显示具体继承值；输入、粘贴、单位切换和快捷标签超过已知模型上限时弹出原因提示并恢复先前值。两区不显示常驻的继承来源、限制原因或越界说明。仅存储用户收紧的字段，单独声明推理时未修改的控制方式、档位和预算边界仍继承；打开、保存和后台刷新不固化继承。公共配置变化时继承项更新，显式限制保留并重新校验。上层收紧使旧限制越界时保留记录，保存时明确报错，来源发布及运行解析均拒绝继续使用，用户需修改上层或恢复默认。取消关联或字段开关不删除表单内暂存值，重新开启恢复；恢复默认则明确清除该组限制。工具形式仍只在关联行声明，不在两组重复。勾选表示供给声明，不表示已实测。

流式限制用现有复选框维护。接口不支持时不可勾选；接口支持时默认继承，取消保存为关闭限制，选回当前默认或恢复默认移除限制。旧未确认例外原样保留到用户修改或恢复，不新增未知下拉选项。此前允许接口差异独立增加模型能力的规则由本节取代。

| 页面选项 | 含义 | 新建模型 / 新增接口关联的默认值 |
| --- | --- | --- |
| JSON 函数工具 | 以 JSON 参数调用工具 | 勾选 |
| 文本输入工具（custom） | 直接以代码、补丁等文本作为工具输入 | 不勾选 |

两项可同时支持，也可都不勾选。编辑已有记录时，包括已有空数组，都保留原选择；默认值不能覆盖已有声明或迁移数据，也不能以其证明当前 B 的工具约定已满足。

**推理供给事实与客户端使用配置：**

| 内容 | 归属 |
| --- | --- |
| 是否支持推理 | 供应商模型 |
| 支持开关、档位、Token 预算中的哪些控制方式 | 供应商模型，必要时记录接口差异 |
| 实际支持的推理档位 | 供应商模型，必要时记录接口差异 |
| 推理 Token 预算的单位、最小可设预算、最大可设预算 | 供应商模型，必要时记录接口差异 |
| 客户端默认档位、默认预算 | Cable 中的具体模型绑定 |
| `ultra` 客户端使用配置 | Cable 模型绑定，按客户端机制开放 |
| 参数映射、校验及配套行为 | 内置适配代码 |

移除“推理开关默认状态”。客户端默认档位与上游省略参数时采用的档位是不同概念，不从后者自动生成前者；供应商表单不填写客户端默认档位或默认预算。同一供应商模型可被多个 Cable 复用，各绑定独立设置使用默认值。

同一模型可组合多种控制方式，也可能支持推理但不可调节。用户只声明实际供给，不编辑上游字段路径、转换表达式或映射脚本；实际字段名称、结构、档位别名与转换由代码按已支持组合维护。

页面分区命名为“推理能力”，控制方式按“支持开关控制 / 支持档位控制 / 支持设置token预算”顺序展示；模型公共能力与接口差异使用相同名称和顺序。

**档位选项与语义：**

- 已知档位包括 `none / minimal / low / medium / high / xhigh / max`。勾选“支持档位控制”后显示全部标准档位选项；取消勾选隐藏分区，保留选项及当前值。协议说明、模型及内置适配规则决定参考勾选值，用户声明实际支持范围，不再填写逗号分隔文本。
- 未知时允许保持未确认，不自动选满；“尚未确认档位”与“不支持推理”分开记录，`none` 表示一个可接受的关闭值，不表示未填写。
- 兼容别名和映射由代码维护，例如 DeepSeek 的 `medium → high`。客户端可用选项按已确认供给和已实现映射生成，不能让用户把客户端别名当成新的上游强度档位。
- `ultra` 不作为独立供应商能力档位；供应商接受并映射到 `max`，也不表示新增了一档实际强度。Cable 仅在客户端实际机制支持时提供对应使用配置。
- 区分“接受某个参数值”与“确实调节推理深度”。例如 MiniMax M3 的非 `none` 值只开启推理，内置规则须表达这一语义，不把多个接受值展示为多个实际深度档位。

**预算事实：**控制方式显示为“支持设置token预算”，勾选该控制方式后显示“推理 Token 预算”分区和“最小可设预算 / 最大可设预算”，取消勾选隐藏分区并保留当前值，说明“该接口允许设置的推理 token 数范围，不代表实际消耗”。首期计量单位固定保存为 `tokens`，不显示“预算计量方式”下拉框；每个数值字段保留 `tokens / K tokens / M tokens` 的显示倍率选择。复用长度组件，允许 K/M 小数及 `4K`、`1.5M` 输入，保存准确整数，不舍入；留空表示未知，校验最小值不超过最大值。已有其他单位仅保留原记录，不提供编辑，不转换为 tokens。预算可能是目标值或硬上限，语义由对应内置适配区分。Cable 默认预算属于使用配置，另在绑定中校验。

固定来源使用其能力；自动多来源绑定按候选共同能力和可映射的控制方式发布，限制取最小值。档位、开关、预算不能仅取数值交集或凭模板互换；没有已实现映射时不开放相应选项或拒绝不支持的请求。未确认能力不能作为承诺，来源暂时离线不扩大客户端目录。

### 4.2 客户端适配由代码实现

适配器根据客户端及版本、访问接口协议、实际/参考模型身份或类型和能力选择已实现规则，处理参数、工具及流式事件、错误、模型目录、历史回放与压缩。供应商名称、实例或预设不决定适配规则；同一已支持组合可复用于多个实例。能力声明用于约束已有实现，不会自动生成新协议适配器。

新增类型需要实现、验证和发布代码。未支持的组合可以保存为待配置，但不能通过选择模板或声明能力绕过实现检查；跨协议转换按第 6 节开放。页面不提供自定义映射、工具转换、历史策略或适配脚本编辑器。

### 4.3 Cable 选择客户端提示词策略

以下表格保留通用默认策略。2026-10-23 更新的 Codex 设计以第 5.2.2–5.2.3 节为准：用户可显式选择某个 Codex 原生模型的提示词作为当前绑定的使用配置，提示词来源与上游实际/参考模型身份分别保存；非原生身份本身不作为禁止选择的理由，能否应用由实际适配和工具约定检查决定。不再使用 CableTidy 自写兼容提示词。旧兼容策略记录保留以供修复；未选择原生提示词时阻止应用与请求，不自动指定提示词。

| 模型情况 | 默认策略 |
| --- | --- |
| 已确认对应客户端原生模型 | 使用对应版本的原生模型定义和提示词；代码按客户端模型 ID 生成目录，并收紧供应商限制 |
| 已实现支持的非原生模型类型 | 要求用户显式选择本机 Codex 原生模型的提示词，校验工具约定；保留已实现的参数、工具与历史适配 |
| 实际/参考模型身份未知 | 保持未知状态并阻止发布；选择原生提示词不能绕过模型身份与适配实现检查 |
| 已知原生模型不在本机目录 | 更新客户端或由代码补齐对应定义，选择提示词不能补齐实际模型缺失的原生定义 |

Codex 原生身份默认推荐对应模型的原生提示词；非原生身份没有默认提示词，须由用户选择本机目录中的原生提示词。选择时校验工具约定，选择提示词不能改变接口协议、创造模型能力或修改历史规则。用户不新增、编辑或保存自定义模板；项目规则继续由客户端管理。

策略按客户端实际支持的模型、Agent 或会话粒度选择；全局策略保存在 Cable，逐模型策略仅在客户端确有机制时保存在绑定。预览展示生效范围、模板与原生定义版本、配套工具约定。实现可用与真实模型验证通过分别展示。

### 4.4 Cable 模型绑定的推理使用配置

绑定提供客户端默认档位、默认预算，以及按客户端机制开放的 `ultra` 配置；不在供应商模型中保存。选项受该绑定的有效供给事实、内置映射、客户端及版本机制共同约束，未实现的控制方式不因供应商勾选而开放。

- 默认档位从该客户端可使用的选项中选择；上游省略参数的默认行为不等同于客户端默认值。
- 默认预算仅在预算控制和对应映射已支持时展示。token 计量复用长度组件，准确保存整数、留空表示未配置；有已知供给上下限时必须符合范围。
- 多来源绑定按可用共同能力及映射约束默认值；来源或供给范围变化后重新校验，不能默默截断预算或改选档位。
- 生效粒度遵守客户端实际机制。绑定保存不同默认值不等于客户端能逐模型应用；不能逐模型生效时明确说明范围和冲突，不生成无效配置。

### 4.5 客户端配置的实施方式（逐项交付）

| 客户端 | 适配落地方式 |
| --- | --- |
| Codex | 原生模型复制对应版本的完整定义；非原生/自定义 ID 生成匹配目录，保留工具约定并显式配置指令、能力和限制。支持时使用 provider 的远程目录，否则生成本地目录并检查全局作用域冲突 |
| Claude Code | 使用真实 Claude 身份映射、模型选择和可生效的能力机制；非 Claude 类型需单独实现与验证内置兼容规则和模板。提示词追加/替换或 Agent 配置受客户端实际作用域限制，不能假设 `/v1/models` 自动选择提示词 |

目录和模型列表只发布该 Cable 显式开放的模型，不能直接转发供应商全部发现结果。客户端自带选项和内部辅助请求按其机制配置；确实无法收敛时在预览中说明并要求明确辅助模型绑定，不隐式扩大路由范围。

全局提示词或目录配置影响多个模型时，生成器检查共同兼容性。无法共存的配置建议拆成多条同类型 Cable，并使用隔离的启动配置；不声称网关改名能触发客户端重建提示词。

## 5. 管理页面逻辑

导航为 **供应商、Cable、审计**。客户端提示词策略在 Cable 内选择和预览，不设预设管理、用户模板保存或通用适配编辑入口。

### 5.1 供应商管理

列表、新建与详情分别为独立页面，沿用 `origin/main` 的线路列表、配置分区、表格、按钮、表单及移动端规范。列表展示名称、状态、接口数和模型数，不嵌入新建或详情表单。供应商管理只维护接口和模型，不展示使用情况、引用 Cable 数或引用绑定列表。

- **新建页面**：基本信息、接口和模型分别使用独立 `panel` 及 `panel-header` / `panel-body`。填写供应商名称，在接口列表通过“添加接口”弹窗录入一个或多个协议、根 URL 及认证；模型列表通过“添加模型”弹窗录入模型供给事实，并关联已添加的接口。允许先不填写模型，创建时至少有一个接口。供应商和接口 ID 由系统生成，用于稳定引用；不要求用户填写，也不按名称重新生成。无供应商类型或预设选择步骤。接口和模型在创建前保存为页面草稿，支持编辑和删除；点击“创建供应商”后一次性校验并保存全部资源，失败不留下部分供应商配置。创建后进入详情。
- **基本信息**：详情以三个并列独立 panel 展示基本信息、接口和模型，沿用诊断/设置页结构，不共用外层 panel 或表单。基本信息单独保存名称及启停状态，接口与模型各自通过弹窗保存资源；名称变化不改变内部 ID、模型记录键或 Cable 引用。
- **接口表**：与模型表并列的独立资源表，展示名称、协议、地址及认证状态，尾列提供测试连接、发现模型和删除；发现模型仅用于已支持的 Responses 接口。点击接口名称进入编辑，测试和发现使用已保存配置；新建页的未保存接口仅提供删除。添加/编辑使用弹出表单，提供流式响应与响应 ID 续接能力开关，默认分别开启、关闭。认证选项随协议变化，由内置方式决定凭据字段与必填条件，用户不编辑认证头或前缀。已有凭据留空保留；无需认证时不要求凭据、不发送认证。旧自定义认证可保留原配置，不开放新自定义方式。未交付协议明确标为暂不适配，不能据此宣称真实接口验证通过。
- **模型表**：展示上游模型 ID、实际/参考模型身份及版本、可访问接口，操作列只保留删除；点击上游模型 ID 编辑。添加/编辑使用独立弹出表单，结构与默认值如下。手动录入或从指定接口发现，候选经确认供给事实后保存；无历史方式选择或接口独立模型 ID。保存失败保留输入，取消有修改时确认放弃。不同 ID 保留独立记录，同 ID 发现结果提示重复，不自动覆盖人工确认内容；发现不加入任何 Cable。

**模型表单的目标顺序：**

| 分区 | 内容与交互 |
| --- | --- |
| 基本信息 | 上游模型 ID、上游模型名称（可选）、实际/参考模型身份（可未知）、身份依据 |
| 能力与限制 | 前两个字段为上下文长度、最大输出长度；输入类型单独成组；保留推理能力和并行工具调用复选框 |
| 推理能力 | 勾选“推理”时显示，取消勾选时隐藏整个区域但保留字段和值。依次展示“支持开关控制 / 支持档位控制 / 支持设置token预算”；勾选“支持档位控制”显示全部标准档位，勾选“支持设置token预算”显示预算分区及“最小可设预算 / 最大可设预算”；取消对应勾选隐藏分区但保留字段和值，模型不支持的参考选项不勾选，未知不预选全部，无单独计量方式选择。没有客户端默认档位、默认预算或推理开关默认状态 |
| 可访问接口与接口供给能力 | 合并成下表一套组件；勾选接口后配置该行工具形式，必要的模态、推理和限制差异归入对应行的展开区域 |

**模型名称与身份：**上游模型名称仅用于友好展示，请求始终使用上游模型 ID。身份候选显示为“模型名称（模型 ID）”，可按名称或 ID 搜索，保存身份 ID；版本差异使用不同身份 ID，不提供独立实际版本字段，也不实现旧版本字段迁移。

**按模型身份填充：**选择已知身份后，自动填入尚未手动修改、且没有已有保存声明的公共能力和限制，以及推理支持方式与实际档位；再次切换身份可以更新先前自动生成的值。手动清空、取消勾选也是用户修改，自动填充保留。能力与限制标题栏尾部提供“按模型身份填充”小按钮，显式恢复公共参考值；没有明确参考的长度或预算留空，未知并行工具能力保留当前选择。“推理”复选框继续控制“推理能力”区域是否显示，自动填充更新该勾选后沿用同一联动；区域内的控制方式始终保留；档位和预算分区分别依赖“支持档位控制”和“支持设置token预算”勾选显示，隐藏时保留字段和值。模型身份只填充参考勾选值，不删除标准选项；公共模型和接口单独声明使用相同联动。隐藏区域不清空字段和值；接口差异中的“能力确认 → 推理”控制单独声明入口：未勾选推理时隐藏入口及其配置，勾选后恢复入口；此时“单独声明此接口的推理能力”控制下方声明区域，未勾选时隐藏并继承公共推理声明，勾选后显示。两层取消和再次勾选都保留当前表单值。保存时，单独声明勾选会保留接口推理差异，即使接口推理支持已取消；实际是否可用由接口有效能力决定。关联能力以模型公共值为上限，只能收紧；上层未声明支持时选项保留但不能开启，尝试开启时弹出原因；旧越界记录在保存时明确报错且不可保存或运行。是否使用接口及折叠状态仍由用户操作。未知身份禁用按钮，仍可手动维护供给事实。

供应商总上下文 `contextWindow` 和最大输出 `maxOutputTokens` 使用逐型号核实的官方模型规格；GPT 参考值独立于本机 Codex 目录，附来源与核实日期。未知型号的长度不从 Codex 目录推断。六个首批兼容模型继续使用其官方资料。兼容资料区分实际档位和接受的别名，MiniMax M3 的非 `none` 值只启用推理，不表示多个深度。参考填充不表示这家服务已经验证通过；用户应按接口和部署事实修正。公共值变化会更新继承它的接口能力，显式接口差异、JSON/custom 工具形式、流式及续接能力、接口选择、上游 ID、版本、身份依据和 Cable 选择均保留。未知 custom 不从模型身份推断。

输入类型常见项为文本、图片、音频、视频，页面只展示实际已支持项；文件上传不归入模型模态。并行工具调用的未知模型新建默认勾选和工具形式的新建默认值均遵守第 4.1 节，编辑不覆盖原选择。

| 使用 | 名称 | 协议 | 地址 | 支持的工具形式 |
| --- | --- | --- | --- | --- |
| □ | 接口名称 | 协议类型 | URL | □ JSON 函数工具　□ 文本输入工具（custom） |

“使用”只表示供应商模型可通过该接口访问，不表示加入任何 Cable。接口列表位于“能力与限制”和“推理能力”之后，不再在前面另设“可访问接口”分区。工具配置只有该行一处；未选接口时不保存其供给声明。选中已有关联保留工具形式，新建模型或首次新增关联默认选 JSON、不选 custom。每个接口关联下两区独立展开查看，长度留空时恢复继承并显示公共值，保存和再次编辑保持关联与准确值。

**长度输入组件：**上下文长度、最大输出长度、对应接口差异及 token 计量的推理预算复用数值、单位识别、换算和精确存储机制。长度保留现有短单位标签，预算按本次结论显示完整单位名称：

```text
[数值] [tokens / K / M]　128K = 128,000 tokens
快捷标签（长度字段）：64K　128K　256K　512K　1M
[预算数值] [tokens / K tokens / M tokens]　4K = 4,000 tokens
```

- `K = 1,000 tokens`，`M = 1,000,000 tokens`；K/M 允许小数，支持直接输入或粘贴 `128K`、`1.5M` 并识别单位。准确的 token 数可选择 `tokens` 直接填写。
- 换算值放在数值和单位后面实时显示；长度单位显示 `tokens / K / M`，采用较窄选择框，把空间留给数值。预算复用换算组件，显示 `tokens / K tokens / M tokens`。快捷标签采用现有小按钮，匹配当前完整值时绿色强调，允许手动修改，移动端自动换行。
- 上下文快捷标签为 `64K / 128K / 256K / 512K / 1M`；最大输出快捷标签为 `4K / 8K / 16K / 32K / 64K / 128K`。接口长度差异使用相同标签。推理预算复用数值、单位和换算交互，不直接套用上下文或输出的快捷值。
- 新建长度保持留空，不自动选择快捷标签；模型长度留空表示未知，接口差异长度留空表示继承。保存统一为准确整数 token，重新编辑不舍入，无法得到整数的输入报错；token 预算允许的零值由对应供给与适配规则决定，不能直接沿用长度必须为正数的约束。

模型表单删除“供给验证”分区，不提供人工选择“部分通过 / 已验证”的入口；旧记录保留方式见第 5.4 节。

修改上游模型 ID 或删除模型记录时，仅提示旧引用不会迁移、相关绑定将变为“来源不存在”，不展示使用情况。失效状态及显式重新绑定在 Cable 管理中处理。供应商及接口删除仍校验引用约束，存在引用时提示先在 Cable 中解除引用，不增加供应商侧的引用管理入口。

### 5.2 Cable 创建

#### 5.2.1 已确认的交互方向

- **多个独立 Panel**：将原先包住全部创建内容的单个 Panel 拆开，各区域拥有自己的标题与内容，不再共用外层 Panel；在同一页面编辑，不要求四步向导。Panel 拆分不等于分别提交，创建时仍一次保存整条线路。
- **默认模型融入模型列表**：移除单独的“默认模型”区域与下拉框，通过模型行的“设为默认”勾选项设置。默认模型仍是线路的一个可选属性，不新增独立业务对象或管理功能。
- **按客户端设计模型配置**：共享线路身份、客户端类型、保存与应用等基础概念；模型选择、绑定字段、默认值、提示词及辅助模型配置遵守各客户端机制，分别设计表单。其他客户端不直接套用 Codex 的模型绑定表单。
- **Codex 逐条添加**：以模型列表为入口，一次添加一个模型并配置其来源和使用参数。取代当前 Codex 创建页“先批量勾选候选，再加入绑定，再展开编辑”的主流程。同一客户端仍可建立多条线路，一条线路仍可使用多家供应商。
- **本版单来源绑定**：每个客户端可见模型只绑定一个上游来源；需要使用两个上游模型时添加两个客户端可见模型，不设置合并来源或次级“管理来源”入口。
- **客户端标识**：自动生成客户端模型 ID，同时允许用户修改；在线路内唯一，保存后保持稳定。
- **Codex 使用配置**：支持配置默认推理档位，以及选择使用哪个 Codex 原生模型的提示词；选择上游模型时，依据实际/参考模型身份自动预填这两项，保留用户调整能力。

供应商继续维护接口、认证、模型身份和供给能力；线路引用这些资源，并保存客户端模型 ID、使用配置及内置提示词策略。供应商发现或新增模型不自动加入线路。

**自动生成与预填规则：**

- 客户端模型 ID 由模型标识生成符合客户端约束的初始值，冲突时自动补充后缀；用户可编辑。尚未手动修改的新建 ID 可随模型选择更新；手动修改或保存后的 ID 不再被自动覆盖。
- 实际/参考身份精确匹配本机 Codex 原生模型时，预选该模型的提示词；推理档位取供给与原生模型定义的有效范围，目录所需的默认值由该范围及 Codex 原生定义确定，不提供线路覆盖。
- 非原生模型使用代码维护的、已验证可用的身份到使用配置推荐关系；没有明确推荐时保持未选择并提示用户选择，不取目录第一项、不按相似名称猜测。原生推荐档位不受当前来源支持时同样不猜测替代档位，由有效客户端模型定义决定；生成目录时必须校验其默认值也属于有效范围。
- 新建表单仅更新尚未被用户修改的字段。手动选择、主动清空、已有保存值和保存失败后的输入都保留；切换模型或接口后重新校验，失效的手动配置显示问题，不能静默替换。
- 提供“恢复推荐配置”操作，重置提示词和工具发现开关，并回填两个上下文窗口的推荐数值，不改客户端 ID。刷新模型目录只更新候选和推荐信息，不自动改变已保存的使用配置。
- 提示词来源与推理档位互相独立。更换提示词来源不将该原生模型的推理档位、上下文或能力覆盖到当前上游模型。

每次添加只配置一个来源，形成一个独立的客户端可见模型。添加第二个上游模型时再创建一个模型条目，不向已有模型追加来源。取消此前提案中的次级“管理来源”入口；已有多来源数据按第 3.2 节单独处理，不静默降为单来源。

**模型列表与默认值：**

- 建议列为“模型名称 / 客户端模型 ID、供应商与上游模型、配置摘要、默认、操作”。点击模型名称编辑；配置摘要呈现默认推理档位、提示词策略及待配置问题。不显示来源数量或选源控件。
- “设为默认”最多勾选一行，勾选新模型自动取消旧模型；取消当前勾选后允许没有默认模型。它控制 Codex 的默认使用模型，不决定模型是否加入线路，也不改变模型推理档位。
- 首次添加模型不自动设为默认；移除默认模型时清空默认选择并提示，不自动选下一条。修改客户端模型 ID 时同步更新默认引用。
- 新增不完整或不受支持的模型可保留为待配置草稿，不发布给客户端，也不能新设为默认。已有默认模型因供给变更失效时保留选择并标明问题，阻止应用，避免静默改选。
- 不提供额外模型别名设置：以客户端模型 ID 完成 Codex 的选择与映射；旧绑定的 `aliases` 在加载、保存、迁移及导入时移除，不再生成额外目录条目。

**保存与应用边界：**

“保存 Cable”与“应用到客户端”分开。缺少来源、代码适配实现、兼容提示词或协议转换时可保存草稿，未通过检查的绑定不发布；默认模型不可用时阻止应用，并明确提示需要修复的项目。

配置完整性、代码支持检查与真实模型验证分开。已实现组合选择原生提示词且静态检查通过时可标记为“使用所选 Codex 原生提示词，尚未实测”，不能把“可选择提示词”当作“类型适配已实现”。

默认推理预算与 `ultra` 继续按第 4.4 节分阶段开放，本次交互调整不新增其可操作入口。已有迁移值完整保留并展示处理提示。不开放用户参数映射、工具转换、历史规则或自定义提示词模板编辑。

**后续实施验收方向：**多个 Panel 无外层包裹；逐条添加、编辑、取消及失败保留草稿；多供应商模型共存且每个客户端模型只有一个来源，两个上游模型生成两个独立客户端选项；无合并来源或手动选源入口；默认选择互斥、可清空且删除/改名正确联动；供应商变化不扩大开放模型；已有多来源数据不静默丢失，迁移推理配置保留，旧模型别名移除；待配置模型不发布；保存不自动应用；桌面与移动端模型列表、弹窗及操作可用。具体实施以最终确认的提案范围为准。

补充验收：ID 自动生成且可编辑；身份匹配时正确预填提示词与受支持的推理档位；未知身份、目录缺失或推荐不适用时不猜测；用户修改和主动清空不被重选/刷新覆盖；恢复推荐配置仅影响使用配置；提示词选择独立保存且正确进入对应客户端模型目录；不借用提示词来源的能力声明；全局指令覆盖冲突可在应用前发现。

#**客户端 ID 与显示名称：**两者独立保存。客户端 ID 默认由供应商名称与上游模型 ID 用 `/` 连接，空白转换为连字符，保留名称大小写和中文，重名追加数字；保存后不随供应商改名而变化。客户端 ID 写入 Codex 模型目录的 `slug`，用于默认模型、客户端请求及路由匹配；显示名称写入 `display_name`，不参与上游路由。新建时优先使用上游模型名称，其次是已知实际/参考身份的名称，未知身份回退上游模型 ID。默认生成“名称 · 供应商名称”，在线路内遇到重名再尝试“名称 · 供应商名称 · 上游模型 ID”，最后追加从 2 开始的数字序号。仅为当前模型生成名称，不重命名已有模型。自动名称在切换上游时更新，手动编辑或清空后不再自动覆盖；绑定的 `nameMode` 保存 `auto` / `manual`，编辑和导入导出保留该状态。打开已有模型、刷新目录或新增其他模型均不触发重命名。

### 5.2.3 Codex 原生提示词读取核实与实现边界

2026-10-23 核实结果：

- [官方命令文档](https://learn.chatgpt.com/docs/developer-commands#codex-debug-models)说明 `codex debug models --bundled` 可导出当前二进制内置模型目录，无需刷新远端模型接口。本机 `codex-cli 0.162.1` 实际导出 11 个条目，均包含非空 `base_instructions` 与 `model_messages.instructions_template`，并带有默认推理档位及支持档位。部分模型提示词相同，不假设每个模型都有独有文本；候选来自实际读取的目录，不硬编码本次条目数量。
- [官方自定义目录示例](https://learn.chatgpt.com/docs/enterprise/bedrock-through-litellm#prepare-the-client-catalog)要求以对应版本完整模型条目建立自定义别名，并保留模型指令等元数据；[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)提供本地 `model_catalog_json` 和 provider 的 `model_catalog_url`。这支持通过客户端模型目录承载逐模型指令。它并不直接证明任意原生提示词与任意第三方模型的组合已兼容。
- 本项目 `src/catalog.rs` 已调用上述命令读取目录；`src/codex_adapter.rs` 已在原生模型分支复制对应模型定义与指令。当前实现允许用户指定另一个原生模型作为提示词来源；原生身份默认推荐对应提示词，非原生身份必须显式选择。自写兼容提示词已移除。

实现时为绑定单独保存提示词来源模型 ID，以及所使用目录的 Codex 版本和内容版本信息；完整保留对应版本的指令结构，避免只改 `base_instructions` 却残留旧模板。应用时按客户端模型 ID 生成对应条目，同时保持上游真实身份、供给限制和适配规则独立。跨模型提示词选择需检查工具形式和相关指令机制，不能通过复制整个来源模型的能力来伪造兼容；不能应用的组合允许保存待配置并说明具体原因。

“使用的提示词”指模型目录中的基础指令/模板，不等同于会话最终完整提示词；项目规则、环境与工具信息仍由 Codex 按运行时机制组合。现有根级 `model_instructions_file` 可能覆盖逐模型指令，继续在预览/应用时提示冲突或使用隔离启动配置。目录读取失败或所选条目消失时保留原选择并说明状态，不静默换模板；已有已应用产物不被后台刷新改写。

### 5.3 Cable 列表与详情

列表展示 线路ID（旧接入模式仍为名称）、客户端、供应商数量/摘要、开放模型数、服务状态和客户端配置状态。按客户端筛选但不限制线路数量。

详情按客户端分别组织模型配置。Codex 拟复用第 5.2.2 节的独立 Panel、模型列表与编辑弹窗，默认模型在模型行设置；以下为详情承载的业务内容，不要求每项独立建 Panel：

- 供应商与模型：编辑绑定引用的供应商模型记录及访问接口；Codex 候选模型在添加/编辑弹窗内选择。模型列表与详情展示客户端 ID、上游模型 ID、实际/参考模型身份、供应商/接口和问题。旧模型记录移除后仍显示原客户端 ID 和旧上游 ID，标为“来源不存在”，允许用户显式重新绑定。
- 模型使用配置与提示词：具体绑定分别管理客户端推理默认值和可用的 `ultra`，选择提示词，查看模板、代码适配版本与实际生效范围；能力事实只读并链接供应商配置。本版只显示与编辑唯一来源，无来源组或路由策略控件。
- 客户端配置：预览、应用、撤销或导出隔离启动配置。显示目标配置位置、当前激活 Cable、共享字段影响和是否需要重启。

修改客户端类型后重新评估全部绑定，保留用户选择并将不兼容项标为待配置。供应商或来源变化后重新校验；目录/提示词变化标记需重新应用，仅连接信息变化更新运行配置。

多条 Cable 可同时运行。应用 B 到与 A 相同的配置位置时预览激活切换，管理共享字段的所有权和恢复记录；撤销 A 不得覆盖 B 或用户后续修改。运行中的旧客户端仍连接原地址，不因激活切换迁移其会话。

### 5.4 验证记录与模型表单

### 6.2 运行与切换约束

运行顺序先校验模型与协议能力，再应用历史/亲和约束，最后按可用性和策略选源。自动路由、均衡与故障切换分别配置，任何策略都不能扩大用户选定的候选范围。

同一客户端模型 ID 不同来源之间的能力与历史约定在发布时确定。请求上游时使用选中供应商模型记录的模型 ID，不使用客户端别名替代。签名、加密推理、远端响应引用和原生压缩结果不能假定跨供应商可重放；策略不兼容时固定来源或拒绝切换。已发送的回答不与新来源结果拼接，来源变更不能绕过这些边界。

引用的模型记录不存在时，相关绑定失效并返回“来源不存在”错误；即使有其他候选，也不把记录移除当作临时故障自动切换。由用户显式移除旧来源或重新绑定，完成校验后恢复使用。这与已配置有效来源的暂时不可用及后续故障切换区分处理。

新 Cable 默认拒绝未绑定模型。旧透传线路迁移时保留其行为，并显式指定唯一兜底供应商接口；不把未知模型广播到所有供应商，也不将其列为自动路由候选。

## 7. 审计、生命周期与迁移

审计记录 Cable、客户端类型/版本、客户端模型 ID、内置适配器与提示词策略版本、访问接口、请求发生时的供应商 ID 与上游模型 ID、实际/参考模型身份（含未知状态）、能力修订与验证状态；推理记录客户端请求选项及实际生效控制方式和值。多来源额外记录候选、排除原因、选源原因、亲和和各次尝试。保存请求时修订号及脱敏的生效配置，保留现有检测、响应和错误审计。供应商模型记录删除或上游 ID 修改后，历史审计仍保留请求时的原值，不随当前目录改写；失效绑定的请求记录旧引用及“来源不存在”错误，不记为已调用新模型。

新供应商及接口 ID 由系统生成；既有供应商和接口保留原稳定内部 ID，不要求重新填写或重新编号。Cable 模型绑定由 Cable 内唯一的客户端模型 ID 管理。供应商模型记录仅使用“供应商 ID＋上游模型 ID”唯一键，不设内部稳定记录 ID。删除 Cable 不级联删除供应商、模型记录或凭据；撤销客户端配置继续遵守字段所有权。停用或移除某个来源只影响相关绑定，不能使其他无关模型一并失效。

迁移把现有上游转成供应商接口，当前单上游关系转成 Cable 的单来源绑定；把供给事实与客户端选择分开，缺乏依据的能力保留为未确认。旧模型定义选择转成可对应的内置提示词策略；无法转换的数据保留为迁移记录并标明待处理，不新增通用编辑器。保留线路 ID、地址、凭据、默认模型、模型映射、透传和恢复记录，不按名称或地址自动合并供应商。旧 Route/Virtual Provider 可作临时兼容结构，页面不要求用户维护它们。

6. 新建模型及新增接口关联默认勾选 JSON、不选 custom；编辑已有记录保持 function/custom 和空数组原值，不从 JSON 推断 custom。合并表格每行独立保存接口工具形式和必要差异，未选接口不参与供给；取消、失败重试和移动端换行正确。
7. 已知身份可自动填充未修改公共值；六个兼容模型与本机原生模型按来源提供参考值。勾选“推理”显示“推理能力”区域，取消勾选隐藏区域但保留字段和值，再次勾选恢复原配置；档位和预算分区分别随对应控制方式勾选显示，取消及再次勾选保留原值；全部标准选项不随模型身份删减，接口差异中的“推理”控制单独声明入口，声明区域仅在接口支持推理且勾选单独声明时显示；两层取消及再次勾选保留原值，显示时保留完整选项。继承公共值的接口随公共值变化，显式接口限制只能关闭已支持推理，不能独立增加公共模型未声明的推理能力；保存和重开保留差异及暂未启用的声明。手动修改、清空、取消勾选、已保存声明、刷新和失败重试均不被自动覆盖；按钮显式恢复参考值，接口例外、工具形式和身份依据保留。Kimi K3 的上下文及最大输出 1,048,576 tokens 保存和重开准确，MiniMax M3 未明确的输出限制和未知预算不猜测。桌面/移动端按钮及字段无横向溢出。
8. 关联区按“模型在此接口下的能力”和“此模型支持的接口能力”独立折叠，无外层折叠区，分别有恢复默认按钮；折叠摘要仅使用本节确定的四条短提示并随显式限制切换，展开后隐藏，互不影响另一折叠区；模型组显示准确继承长度，接口组显示流式响应复选框；继承接口开启和关闭值，未设置例外时保存仍不生成独立配置。测试接口默认值变化及后台刷新，继承项自动更新、显式例外保持原值，其他未保存字段保留；点击“恢复接口默认”或手动选择当前默认值移除例外，保存及重开继续继承；既有未知例外不因打开或保存被改写。能力、输入类型、控制方式和档位只能收紧；接口长度输入、粘贴、单位切换及快捷标签超过模型已知上限时立即提示原因并保留原值，不生成例外；等于模型上限或留空时恢复继承。上层不支持的选项保留且未勾选，鼠标和键盘尝试选择时弹出原因，不改变声明。两区不显示常驻提示；长度及预算越界保存和运行均拒绝，越界旧记录在保存时明确提示。桌面和移动端沿用现有复选框及文字按钮样式。
9. 不因本次默认值、单位展示或组件合并改变 Cable 的显式选择、接口关联、上游 ID 和已知准确值；迁移中不能确定归属的数据明确待处理。模型表单不展示“供给验证”或人工验证选择，新建模型不生成验证字段，编辑保留旧记录。

### 2026-10-24：供应商长度与 Codex 窗口分离

- 供应商模型的 `contextWindow` 为总上下文能力，`maxOutputTokens` 为最大输出能力。接口差异可收紧，两者不代表客户端默认策略。已保存的 272K 等值不做猜测性批量更正；用户显式填充参考值时才更新。
- Cable 逐模型绑定的 `codex.contextWindow` / `codex.maxContextWindow` 保存客户端使用窗口及窗口上限。留空沿用默认策略，界面显示最终值及其来源。窗口控件属于“使用配置”；“恢复推荐配置”由服务端默认策略计算并回填两个窗口的具体数值，保存为显式使用配置。
- 原生默认策略来自同身份的本机 Codex 目录，最大窗口按已知供给收紧，默认使用窗口再按最终最大窗口收紧。供应商总上下文超过原生目录最大窗口不再报错。显式扩大客户端上限须有供给事实支持，且使用窗口不得超过上限；显式错误报错，不静默截断。
- 兼容适配使用明确的 272,000 tokens 默认窗口，并受供给限制；默认最大窗口取供应商总上下文。更换提示词不会改变此策略，也不继承提示词模型的窗口。
- 运行视图以 `clientContext` 传递客户端设置，与供应商 `contextWindow` 分开。目录生成、草稿预览、应用与隔离启动使用同一计算逻辑；导入导出保留绑定中的窗口设置。
- 旧客户端窗口迁至绑定的两个窗口字段，不再声称为供应商能力；迁移后的供给总上下文保持未知。无法确认的既有供应商声明仍保留。
- 不引入自动压缩功能，不新增压缩字段、控件或阈值计算。已有 Codex 压缩配置保持原样，应用与恢复沿用既有窗口托管机制。

GPT-5.5、GPT-5.6 Sol/Terra/Luna、GPT-6 Astra/Sol/Luna、GPT-6.1 Sol 的长度参考均于 2026-10-24 逐个核实为总上下文 1,050,000、最大输出 128,000 tokens。来源为各型号的官方 API 页面，例如 [GPT-5.5](https://developers.openai.com/api/docs/models/gpt-5.5) 和 [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)；这些数值不作为未知 GPT 型号的通用默认。
