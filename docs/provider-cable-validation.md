本分支实现 A+B：Codex 原生 GPT 定义，以及 GLM-5.3、GLM-5.3-Flash、Kimi K3、DeepSeek-V4-Pro、DeepSeek-V4.1-Flash、MiniMax M3 的 Responses 内置兼容规则。代码和模拟测试通过不代表真实供给验证通过。

**文档范围说明（2026-10-20）：**模型表单简化、推理供给与 Cable 默认档位分离、档位勾选、预算换算、新建工具默认值及合并接口组件已实现。供应商保存供给事实，绑定保存 `reasoning.defaultEffort`；默认预算映射和 `ultra` 配置尚未开放，已有默认预算保留迁移数据并明确阻止应用。“推理控制事实”改为“推理能力”，控制选项按“支持开关控制 / 支持档位控制 / 支持设置token预算”排序，公共能力与接口差异一致。模型表单已删除“供给验证”分区，不提供人工验证状态选择；编辑保留已有人工记录，新建不生成验证字段。

## 配置与验证步骤

1. 在“供应商”列表点击新建，在独立页面填写服务名称，通过接口列表的“添加接口”弹窗添加一个或多个协议接口及认证，再通过模型列表的“添加模型”弹窗录入供给事实；接口和模型可在创建前编辑或删除，确认后一次性创建，ID 自动生成。详情使用基本信息、接口、模型三个独立 panel，各自管理。认证方式决定凭据字段，已有凭据留空保留，无需认证不发送凭据；不填写认证头或前缀。模型记录填写请求上游的模型 ID、实际/参考模型身份及版本、身份依据、可访问接口、输入/推理能力和上下文限制。接口声明流式响应（默认开启）及响应 ID 续接（默认关闭）；模型在能力与推理之后的合并接口表中勾选可访问接口，逐行声明 JSON 函数工具与文本输入工具（custom）；新建模型或新增 Responses 接口关联默认勾选 JSON 和 custom，其他协议默认只选 JSON；编辑已有声明（包括空选择）不补选，其他接口差异按行展开填写。默认和人工声明不表示已经实测。已保存接口的操作列提供测试连接、发现模型和删除，发现模型仅用于 Responses；点击名称编辑。测试和发现使用已保存配置，新建页的接口草稿仅提供删除。未知事实留为未知；供应商发现只返回候选 ID，不替用户判断身份，也不加入 Cable。
2. 模型表单先填写上下文长度、最大输出长度，再分别确认输入类型和模型能力；首期显示文本、图片，编辑保留其他已有输入类型。未知模型新建默认勾选并行工具调用，已有选择不覆盖。“推理”复选框控制“推理能力”分区显示；隐藏保留原字段和值，再次勾选恢复，依次按供给声明勾选“支持开关控制 / 支持档位控制 / 支持设置token预算”；接口差异使用相同顺序及名称。勾选“支持档位控制”显示实际支持的推理档位，勾选“支持设置token预算”显示预算字段；取消相应勾选隐藏分区并保留字段和值，重新勾选恢复。公共模型和接口单独声明使用相同联动。标准档位选项全部保留，协议与内置模型规则只决定参考勾选值。未知保持未确认。“推理 Token 预算”使用“最小可设预算 / 最大可设预算”字段，说明该接口允许设置的推理 token 数范围，不代表实际消耗。字段使用精确 token 数值与显示倍率选择，支持 `4K`、`1.5M`、零预算；留空未知，接口差异留空继承。首期内部固定保存 `tokens`，移除独立的预算计量方式选择，已有其他单位仅保留原记录，不提供编辑或转换。首期只开放档位参数，预算或开关事实不自动启用运行映射。DeepSeek 客户端 `medium` 映射为供给 `high`；MiniMax M3 非 `none` 值映射为开启值 `high`，不作为多个实际深度。B 必须明确声明 function 和 custom 两种工具形式、支持流式并确认上下文限制才可发布；只有 JSON 工具的供给仍可保存，但不满足当前 B 的 freeform apply_patch 约定。
3. 创建 Codex 线路，在独立“模型”Panel 点击“添加模型”，逐条选择供应商、上游模型和接口；每个客户端模型只绑定一个来源。客户端 ID 自动生成且可编辑，推理档位与使用的 Codex 原生模型提示词按实际/参考身份预填，手动修改和主动清空不被覆盖；无明确推荐时自行选择，可预览提示词原文并恢复推荐配置。添加/编辑先保留页面草稿，最后统一保存。默认模型在列表行勾选，最多一个、允许不选；不选时应用不固定客户端模型，删除或改名与默认引用联动。每条绑定保留独立使用配置，所选提示词的版本与内容摘要参与应用校验，不借用提示词来源的模型能力。原生 GPT 仍基于本机完整定义，非原生模型需通过已实现的适配与提示词工具约定检查；不再提供自写兼容提示词；旧兼容策略记录仍可加载，须选择本机 Codex 原生提示词后才能应用和请求。更新目录后重启 Codex，B 的无状态完整历史仍由代码决定。
4. 预览后应用，重启 Codex；或者导出隔离配置，把 `files` 按 `path` 写入独立目录，设置 `CODEX_HOME` 为该目录后启动。网页搜索默认继承 Codex 当前配置；基本信息中明确选择 cached、indexed、live 或 disabled 后，应用才写入对应 web_search，只有 disabled 会主动关闭。隔离导出在继承时省略该字段。兼容定义使用普通 Responses、直接函数工具和 freeform `apply_patch`，关闭原生专属代码模式、内部请求及推理更新项。预览明确说明特殊 tool_search 与 multi_agent_v1 尚未适配，网关不向上游发布这两类工具；其他不支持工具拒绝请求。
5. 在临时 Git 仓库中逐模型检查：普通回答、支持的推理档位、流式结束、读取文件/运行命令、用补丁创建并修改文件、接续工具结果的多轮对话。请求审计应保持客户端 ID、原上游 ID、供应商/接口、身份和推理生效值。
6. 同一 Cable 共存原生 GPT 与 B，分别选择并请求。供应商添加新模型后刷新，Cable 的选择和发布目录必须保持不变。
7. 两个上游模型分别添加为两个客户端可见模型，分别检查请求映射；不提供合并来源或手动选源。旧多来源记录可显式拆分，当前来源保留原客户端 ID，其他来源生成新 ID，原记录不会在升级或普通保存时静默丢失。替换单个绑定的来源后检查能力与历史兼容性，必要时使用新会话。删除或修改上游 ID 后检查错误，再显式重新绑定。
8. 应用 Cable A，再应用 Cable B。撤销 A 应拒绝覆盖 B；撤销 B 恢复 A；撤销 A 恢复最初配置。用户修改受管理字段后应保留用户配置并拒绝自动撤销。导入导出需保持选择及来源引用；同名供应商导入为独立实例，无凭据文件不继承本地密钥。

升级既有目录时，旧流式限制保留为模型接口例外，旧用户历史策略移除；工具形式留空，不把“支持工具调用”自动转换为 custom。请确认每个模型在具体接口上的工具形式再重新预览和应用。接口能力、工具形式和例外需在导入导出后保持一致。旧模型公共默认档位与预算迁入引用它的绑定，已有显式值不覆盖；来源不明的接口默认值、旧开关和 ultra 保留迁移记录。迁移的默认预算当前不可应用，可在 Cable 中明确清除。

旧关联越界记录保留并明确报错，不自动增加模型或接口的上层声明。结构合法时管理台仍可启动，可逐条修复；越界来源不进入有效模型目录，也不能运行。保存模型必须修复其全部越界项，其他未修改的旧问题可以暂存但不能扩大；结构错误仍拒绝启动和保存。

## 按模型身份填充的参考值

“实际/参考模型身份”可以选取已知模型。选择时自动填充未修改、未保存声明的公共能力和限制及推理能力；手动清空或取消勾选也会保留。标题栏的“按模型身份填充”按钮可重新填入参考值，未知身份禁用。“推理”复选框控制“推理能力”区域显示，自动填充更新勾选后沿用该联动；隐藏不清空字段和值。区域内控制方式完整保留，档位和预算分区分别由“支持档位控制”和“支持设置token预算”勾选显示，取消勾选不清空字段和值；显示档位时保留全部标准选项，不支持的参考选项只不勾选，用户仍可修改。接口差异中的“能力确认 → 推理”是单独声明的前提：取消推理时隐藏单独声明入口及区域，保留勾选和字段值，恢复推理后按原勾选恢复显示。“单独声明此接口的推理能力”未勾选时继承公共推理声明，勾选后显示声明区域，两层隐藏都不删除选项。保存保留仍勾选的单独声明，即使接口暂不支持推理；实际可用性由接口有效能力决定。模型公共能力是关联的硬性上限，显式限制只能关闭或收紧，保存和重开保留差异及暂未启用的声明。区域内全部标准档位仍保留。接口关联、显式接口差异、工具形式、模型 ID、版本、身份依据和 Cable 选择不会因此改变；继承公共值的接口能力随公共值更新。参考身份和资料不是这家服务的实测结论，不自动记录验证通过。
