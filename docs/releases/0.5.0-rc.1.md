# CableTidy 0.5.0-rc.1

这是 `0.5.0` 的第一个候选版本，基于合入 [PR #61](https://github.com/ZY-WANG-0304/cabletidy/pull/61) 后的 `origin/main`（`0cf6ef3dc5ec8cdfb57d449ac20f1a25f78bae0e`）。以下汇总相对稳定版 `0.4.0` 的变化。候选包发布到 npm `next`，`latest` 保持 `0.4.0`。

## 新增与改进

- 服务“设置”新增独立临时目录，默认使用 `${CABLETIDY_HOME}/tmp`。可填写服务器上的绝对路径，留空恢复默认；保存时检查目录是否可创建及写入，重启后生效，页面显示当前使用目录和待重启状态。目录分为 `spool`（请求、响应和流式事件的加密暂存）、`sqlite`（数据库临时文件）及 `helpers`（辅助脚本）。修改目录不会迁移审计数据库，也不会删除旧目录中的其他文件。见 [PR #61](https://github.com/ZY-WANG-0304/cabletidy/pull/61)。
- Unix 控制 socket 优先放在有效的 `$XDG_RUNTIME_DIR/cabletidy/<数据目录哈希>/<实例 UUID>.sock`；未设置、目录不可用或路径过长时回退到原 `/tmp` 位置。实际地址写入 `runtime.json.controlAddress`，`status`、`stop` 和 `restart` 使用该地址，允许客户端与 daemon 的环境变量不同；旧实例仍可按原规则连接。正常退出清理 socket，重启只清理所选实例目录中的旧 UUID socket。Windows 继续使用用户私有命名管道。
- 会话轨迹概览新增上方请求坐标轴和横向滚动，长会话保持请求柱可读；选中、重新选择及恢复会话时自动把对应请求滚入视野。见 [PR #58](https://github.com/ZY-WANG-0304/cabletidy/pull/58)；该变更此前未纳入 `0.4.0` 安装包。
- 配置身份、配置图和模型编辑、风险内容投影、旧审计兼容定位及模型策略集中到 Rust，前端继续负责表单草稿、导航和展示。配置操作复用修订冲突检查、校验与原子保存，保留共享依赖和原有整图提交接口；风险投影只读，不改写历史证据。修复嵌套重复 JSON 键的证据匹配误判，减少大参数和多项证据同时留在内存的开销；工作区耗尽时保留正文并明确返回风险定位缺口。见 [PR #57](https://github.com/ZY-WANG-0304/cabletidy/pull/57) 和 [迁移记录](../web-rust-migration.md)；该变更此前未纳入 `0.4.0` 安装包。

## 配置与运行兼容性

- `config.json` 版本继续为 `3`，新增顶级 `temporaryDirectory` 字段：绝对路径字符串指定目录，`null` 或缺少字段使用默认位置。该设置不随线路导入导出；已有线路 ID、本地 URL、上游凭据和客户端配置继续沿用，无需因本次升级重新应用客户端。
- Unix 临时目录须属于当前用户且权限为 `0700`；共享目录、非目录和符号链接会被拒绝，程序不会修改已有目录权限。规范化后的完整 `sqlite` 子目录路径最多为 486 字节，保存和启动均检查。Windows 使用目录继承权限，应选择当前用户的私有目录；辅助工具使用兼容 PowerShell 的规范化路径。
- daemon 启动时为 SQLite 设置专用系统临时路径，优先于继承的环境变量。正文加密暂存继续受 512 MiB 共享预算限制，SQLite 临时文件不计入该预算；两者与审计库放在同一分区时会共同消耗磁盘空间。
- `XDG_RUNTIME_DIR` 根目录必须已存在、为绝对路径、属于当前用户且权限为 `0700`，程序不会创建或修改根目录。大体积正文暂存不放入该运行时目录；临时目录设置也不影响 socket 位置。运行时目录通常随登录会话结束，跨注销持续运行需由服务管理器提供稳定目录。
- 审计保存周期、容量预算、配置版本和线路接口沿用 `0.4.0`，旧版本升级所需的字段迁移见 [0.4.0 发布说明](0.4.0.md)。

## 安装与升级

支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。完整 npm 包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64 原生程序；安装不需要 Rust，也不下载额外二进制。源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。

1. 用旧版 `cabletidy stop` 停止服务并确认退出，备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。从 `0.2.0` 升级须先通过原终端 Ctrl+C 或原进程管理器停止，另见 [0.3.0 升级说明](0.3.0.md)。
2. 确认 npm 已提供候选版本后安装并启动：

```bash
npm view cabletidy@0.5.0-rc.1 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.5.0-rc.1 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.5.0-rc.1) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后安装该 tarball。GitHub Release 与 npm 独立发布，npm 可用性以 registry 查询为准。

已支持 `update` 的版本可执行 `cabletidy update 0.5.0-rc.1`，按提示重启；`cabletidy update next --check` 检查候选版，`cabletidy update next` 安装。无参数更新继续使用稳定版 `latest`。启动后核对线路、客户端接管状态、审计记录、设置中的临时目录及重启提示。

## 已知限制与恢复

本版本为候选版。安全审计继续仅记录，不阻断操作、不额外调用模型，也不确认工具真实执行结果。风险定位受共享内存和每页工作区预算限制，当前内容读取仍等待整页标注结束；旧正文缺失或定位缺口不会补造。

临时目录不可用或不满足权限要求会导致启动失败；可在停止服务后把 `temporaryDirectory` 恢复为 `null`，或修正目录后重新启动。临时目录不会自动清理其中不属于当前进程的其他文件，SQLite 临时文件不受正文暂存预算限制。数据目录仍应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享锁协调。

恢复旧版前停止候选版并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。数据库和备份可能包含认证信息、对话及工具内容，沿用原有权限保管；不要同时运行新旧 daemon。

## 发布与验收

发布提交执行版本一致性、格式、严格 Clippy、Rust / JavaScript 测试及安装冒烟验证。`v0.5.0-rc.1` 的 tag 工作流执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台构建和最终完整包安装验证；产物以成功工作流及 `release.json` 中的版本、提交、ref、运行 ID、SHA-256 和 integrity 为依据。

GitHub Pre-release 在工作流成功后自动创建并附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 与标签，并在隔离缓存和数据目录中从官方源验证安装、版本、管理台、停止和重启。

真实 Codex / Claude 上游接入、旧版升级与恢复、长期审计留存与磁盘压力、长会话历史匹配，以及 Windows 真实终端 Ctrl+C 与交互更新没有本候选版的新增人工验收记录。自动化测试不能代替这些验收，完整范围见 [维护者发布流程](../release-process.md)。
