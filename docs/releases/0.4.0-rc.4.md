# CableTidy 0.4.0-rc.4

这是 `0.4.0` 的第四个候选版本，基于合入 [PR #45](https://github.com/ZY-WANG-0304/cabletidy/pull/45) 后的 `origin/main`（`08908db`）。以下汇总相对 `0.4.0-rc.3` 的变化；之前的功能见 [0.4.0-rc.3 发布说明](0.4.0-rc.3.md)。候选包发布到 npm `next`，`latest` 保持稳定版 `0.3.0`。

## 新增与修复

- 请求内容默认折叠可确认的历史区间，优先加载并展开新增条目；提供“跳到新增”和“展开全部 / 折叠历史”切换，历史在原位置按需分页展开，风险定位自动打开对应区间并高亮。区分会话归组与 thread / agent 上下文，依据明确继承关系保守匹配，Claude 最新用户消息中的文本保持展开。切换视图或发起新的风险定位后，旧历史页结果失效，避免过时内容覆盖当前视图。见 [PR #45](https://github.com/ZY-WANG-0304/cabletidy/pull/45) 和 [实现方案](../request-history-folding-and-inspection-reuse.md)。
- 在完整条目指纹和相同检查依赖约束下复用已完成、已持久化的风险检测，包括无命中结果；规则、有效凭据集合或本地配置凭据子集变化后重新检查。前一请求尚未完成检查时继续独立检测，不等待或阻塞代理转发。证据按当前请求重新关联，每条请求仍独立保留完整正文；复用减少重复规则计算，不承诺网络或正文存储同步减少。
- 新增风险与历史风险分别计数和展示，请求行及轨迹区分未发现风险、存在新增风险和仅含历史风险。确认的历史风险不再重复计为会话新增发现，不同调用 ID 的同参数工具调用仍是独立事件。旧记录继续完整查看，不自动回填历史关系、检测完成证明或改写旧统计。
- 修正流式请求完成判定：Responses 使用完整的 `response.completed`，Messages 使用完整的 `message_stop`；合法错误事件独立记录。客户端收到结束事件后关闭连接不再误标为中断，协议结果、连接接收状态与检查状态分别保留。`[DONE]`、跨协议事件、未闭合事件或工具项完成均不能证明响应完整；已确认的流错误不会被残缺尾部覆盖。见 [PR #44](https://github.com/ZY-WANG-0304/cabletidy/pull/44)。
- 检查状态新增 `limited`，页面显示“已检查（覆盖有限）”，将图片、加密内容、未知工具等能力限制与正文缺失、解析或资源缺口分别呈现。启动时对有充分证据的旧记录进行一次保守状态修正；缺少合法结束事件或存在检查缺口的记录保留原判定，正文、字节位置和风险证据不改写。
- 移除会话概览及请求列表中的冗余“工具调用提议”摘要，工具名称仍可搜索，完整调用继续在请求与响应内容中查看。清理未使用的前端、检测器及 Codex 产物字段，停用 Generic CLI 无实际效果的 context-window / compact 控件；旧配置值在编辑和导入导出中继续保留。见 [PR #42](https://github.com/ZY-WANG-0304/cabletidy/pull/42)、[PR #43](https://github.com/ZY-WANG-0304/cabletidy/pull/43)。

## 安装要求

- 支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。npm 包自带原生程序，没有 npm 运行时依赖，安装不需要 Rust，也不下载额外二进制。
- 完整发行包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64。源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。
- Codex 可选模型设置依赖本机支持 `debug models --bundled` 的 Codex CLI；纯透传不依赖该目录。Windows 的模型目录查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 安装与升级

1. 用旧版 `cabletidy stop` 停止服务，确认退出后备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。
2. `0.4.0` 候选版审计数据库保留敏感原文，可能包含认证信息、对话及工具内容；备份和包含凭据的导出文件应按敏感数据保管。旧版已脱敏记录不会恢复为原文。
3. 确认 npm 已发布候选包后安装并启动：

```bash
npm view cabletidy@0.4.0-rc.4 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.4.0-rc.4 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.4.0-rc.4) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后执行 `npm install -g /absolute/path/package.tgz`。GitHub Release 与 npm 独立发布，是否可从 npm 安装以 registry 查询结果为准。

从 `0.4.0-rc.3`、更早的 `0.4.0` 候选版或 `0.3.0` 升级继续沿用 `config.json`、`secrets.json` 及已有审计数据库，无需因本次升级重新应用客户端配置。启动时自动进行审计状态与新增索引结构迁移；历史折叠和检测复用从新记录开始生效。启动后核对已有配置、模型映射、审计记录和新请求的历史展示。查询审计 API 的外部工具需兼容新增的 `inspectionStatus: limited`，并区分能力限制与检查缺口。从 `0.2.0` 或早期 `0.3.0` 候选版升级时，还需遵循 [0.3.0 发布说明](0.3.0.md) 中的停止服务、旧目录锁迁移及客户端配置步骤。不要删除或替换新版持久的普通 `daemon.lock` 文件。

已使用 `0.4.0-rc.3` 时也可执行 `cabletidy update 0.4.0-rc.4`，按提示重启服务。`cabletidy update next --check` 检查后续候选版，`cabletidy update next` 安装；无参数的 `update` 使用稳定版 `latest`，当前候选版高于稳定版时不会自动降级。非交互终端默认拒绝启停确认，自动更新并重启需显式传入 `--yes`。

## 已知限制与恢复

- 安全审计仍为“仅记录”，不阻断操作，不额外调用模型，也不确认工具真实执行结果。无风险发现、检查复用或“已检查”均不表示已证明安全；会话与上下文标识来自客户端，无法可靠匹配的历史保守展开。
- 每条请求继续独立保存完整正文，首版不做正文存储去重、无关会话之间的缓存共享或响应到请求的跨阶段复用。并发请求只复用已经提交的结果，可能产生少量重复计算；旧记录不补造历史关联或阴性缓存。
- 审计默认保留 30 天、容量预算 128 MiB，容量压力下可能提前清理。数据库或队列不可用时代理继续工作，页面显示检查失败、覆盖不足或存储缺口。历史来源清理后，当前记录的留存正文和证据仍可独立查看。
- 默认不含凭据的配置导出会移除上游 URL 中的用户名、密码、查询参数与片段；依赖查询参数的地址需在导入后补齐。导出不携带客户端文件、应用与恢复记录、审计日志和机器设置；配置删除不会自动恢复客户端文件。
- 数据目录应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享锁协调；不包含开机自启或崩溃自动重启。原生程序独立运行时需手动替换二进制，`update` 仅适用于全局 npm 安装。
- 恢复旧版前先停止候选版并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。不要直接让旧版读取已更新的数据代替恢复演练，也不要同时运行新旧 daemon。

## 发布与验收

发布提交需通过版本一致性、格式、严格 Clippy、Rust / JavaScript 测试及安装冒烟验证。`v0.4.0-rc.4` 的 tag 工作流执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台构建和最终完整包安装验证；以该 tag 的成功运行及 `release.json` 记录的提交、ref、运行 ID 和摘要为产物依据。

GitHub Pre-release 在工作流成功后自动创建并附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 与标签，并使用隔离缓存和数据目录验证安装、版本、管理台、停止及重启。

本候选版的真实 Codex / Claude 上游接入、旧版升级与恢复、长会话及 fork / side 历史匹配、配置删除后的客户端切换，以及 Windows 真实终端 Ctrl+C 与交互更新仍需人工验收；自动化模拟测试及此前版本的人工结果不能替代本候选版验收。完整范围见 [维护者发布流程](../release-process.md)。
