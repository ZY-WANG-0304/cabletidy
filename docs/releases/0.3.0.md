# CableTidy 0.3.0

`0.3.0` 沿用 `0.3.0-rc.4` 的功能代码，更新版本号和发布文档后重新构建正式安装包。以下汇总相对上一稳定版 `0.2.0` 的变化。

## 新增与改进

- 服务端迁移到 Rust，Web 资源嵌入原生程序。npm 包保留 Node.js 薄启动器，自带五个平台二进制；安装不下载额外二进制、不编译 Rust，没有 npm 运行时依赖。
- `cabletidy start` 默认在后台运行，管理接口就绪后返回地址和日志路径；`start --foreground` 支持前台运行。`stop` 等待请求排空、持久化和清理完成，`status` 查询实际实例状态。日志自动轮转，每个文件最多 10 MiB，保留三份历史日志。
- 使用操作系统独占文件锁及本地控制通道管理 daemon，修复主机名变化后无法停止的问题。macOS / Linux 使用 Unix domain socket，Windows 使用仅当前用户可访问、拒绝远程连接的 named pipe。取消停止等待会释放连接名额，但不撤销已经接受的停止请求。
- 管理台新增安全审计页面，支持风险筛选、请求与响应详情、正文查看、流式事件时间线和风险定位；修复流式证据高亮及切换详情后的过期请求问题。凭据在落盘前定向脱敏，长正文使用有界内存和加密临时暂存。
- 上游请求支持启动环境中的 HTTP / HTTPS / ALL_PROXY 与 NO_PROXY 设置，包括代理认证、HTTPS 隧道和 SOCKS 代理；修改环境变量后需重启服务。
- 上游模型配置按客户端模型名保存，保留迁移及模型映射调整前的模型设置。开发模式使用独立的数据和客户端配置目录，支持 Rust / Web 文件变化后重启。

## 安装要求

- npm 安装支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。用户安装不需要 Rust；源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。
- 完整发行包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64 原生二进制。独立原生程序不需要 Node.js。
- Codex 可选模型设置依赖本机支持 `debug models --bundled` 的 Codex CLI，纯透传不依赖该目录。Windows 的 Codex 目录查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 安装与升级

1. 停止旧服务。从 `0.2.0` 升级时，在原终端按 Ctrl+C 或通过原进程管理器停止，该版本没有 `stop` 命令。候选版使用旧版的 `cabletidy stop`；若主机名变化导致停止失败，从 `runtime.json` 读取 PID，并使用系统进程工具核对后手动停止对应进程。
2. 确认旧进程退出后，备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）以及 Codex / Claude 配置目录。保留配置、密钥及已有审计数据。
3. 如果数据目录中留有旧版的 `daemon.lock` **目录**，确认旧进程退出后手动删除该目录，否则新版会返回 `ELOCKLEGACY`。新版的锁是持久的**普通文件**，退出后仍保留，不能因为文件存在或 `status` 无响应就删除或替换它。
4. 确认 npm 已发布 `0.3.0` 后安装并启动：

```bash
npm view cabletidy@0.3.0 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.3.0 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.3.0) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后，用 `npm install -g /absolute/path/package.tgz` 安装。npm 的 `latest` 在正式包发布后指向 `0.3.0`。

已有 `config.json` 和 `secrets.json` 继续沿用。安装本身不启动服务，也不改写客户端配置；启动后核对端口、上游、模型映射和可选设置。从 rc.4 升级不需要重新应用客户端配置；从更早版本升级时，仍使用独立代理端口的配置需要重新应用客户端接入以更新地址，旧窗口与压缩设置需要核对后重新应用。

## 已知限制与恢复

- 数据目录应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享目录的锁协调。不包含开机自启或崩溃自动重启。
- 安全审计为“仅记录”，不阻断操作，不额外调用模型，也不确认客户端工具真实执行结果。无风险发现不代表已经证明安全。
- 审计数据库默认保留 30 天、容量预算 128 MiB，容量压力下可能提前清理。正文可能包含对话、输出和命令等敏感内容；凭据定向脱敏不等于所有正文都不敏感。数据库或队列不可用时代理继续工作，管理台显示退化状态和缺口。
- 恢复旧版前先用新版 `stop` 停止并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。不要让旧版直接读取已迁移的数据或含新版普通锁文件的数据目录，也不要同时运行新旧 daemon。
