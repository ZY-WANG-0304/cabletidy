# CableTidy 0.4.0

`0.4.0` 沿用 `0.4.0-rc.6`（`1867081d46aed1fd1d1c060d6fd5f6441da64a0b`）的功能代码，只更新版本号和发布文档，重新构建五平台正式安装包。按维护者选择，本次发布不包含 rc.6 之后合入 main 的 [PR #58](https://github.com/ZY-WANG-0304/cabletidy/pull/58)（轨迹概览坐标轴与横向滚动）。正式包发布到 npm `latest`。以下汇总相对上一稳定版 `0.3.0` 的变化；各候选版本的详细记录见 [rc.1](0.4.0-rc.1.md)、[rc.2](0.4.0-rc.2.md)、[rc.3](0.4.0-rc.3.md)、[rc.4](0.4.0-rc.4.md)、[rc.5](0.4.0-rc.5.md) 和 [rc.6](0.4.0-rc.6.md)。

## 新增与改进

- 审计记录按客户端报告的会话标识归组，并按线路及协议隔离；无标识的请求独立展示。会话轨迹支持连续加载、摘要与客户端 / 上游模型搜索、风险筛选和耗时占比。风险筛选命中会话后保留全部已留存上下文，旧请求链接仍可定位对应记录。
- 请求与响应内容使用独立页签，完整展示 Codex Responses / Claude Messages 的系统提示词、用户与历史模型内容、思考、工具调用及结果、模型输出；支持分类统计、分页、跨页工具关联和精确原文定位。流式响应合并增量与最终输出，缺失、中断和覆盖限制分别提示。详见 [Codex 请求概览](../codex-request-overview.md)、[Claude 请求概览](../claude-request-overview.md)、[Codex 响应概览](../codex-response-overview.md) 和 [Claude 响应概览](../claude-response-overview.md)。
- 新审计记录保留敏感原文，自动高亮凭据、认证头、Cookie、私钥及服务器地址等风险；点击风险可定位请求、响应或检测快照。凭据检测按格式前缀、长度和熵分层，减少自然语言、公开 SSH 地址等误报；服务器地址检测覆盖 IPv4、IPv6 和常见编码形式，区分公网与内网。旧版已脱敏内容无法恢复，普通诊断事件继续脱敏。
- 默认折叠可确认的历史区间并展开新增条目，提供“跳到新增”和历史展开切换；风险定位自动打开对应历史。依据明确的 thread / agent 继承关系保守匹配，复用完整条目已完成的风险检测，包括无命中结果；规则或有效凭据变化后重新检查。新增风险、历史风险与旧版未分类风险分别展示，旧记录不补造历史关系。见 [实现方案](../request-history-folding-and-inspection-reuse.md)。
- 修正流式完成判定：Responses 依据完整 `response.completed`，Messages 依据完整 `message_stop`；客户端随后关闭连接不再误标为中断。新增 `inspectionStatus: limited`，区分“已检查（覆盖有限）”与正文、解析或资源缺口。CableTidy 自身的配置提交、启停、客户端应用和恢复不再计入 Agent 安全审计。
- 管理台新增服务“设置”，调整全部线路的审计保存周期和存储上限。默认保留 30 天、容量预算 5 GiB（5120 MiB）；两项均可独立选择“不限”，有限值至少 1 天和 16 MiB。保存立即生效并在重启后继续使用，保护未保存草稿并处理并发修订冲突。降低上限可能立即清理历史；数据库文件锁或 WAL 暂时阻塞时延后回收，避免健康记录读取失败。
- “配置套装”更名为“线路”（英文 Cable），每条线路仍连接一个上游。支持确认后删除并清理未共享依赖，以及独立的线路导入 / 导出页面、预览、同名线路更新或新建、浏览器前进 / 后退和未保存修改保护。导出默认不含凭据，明确勾选时可携带明文密钥；导入不自动修改客户端配置。
- Claude Code 接管字段被外部修改后，应用或撤销提示冲突字段，取消保留当前文件，确认后先备份再继续。重新应用后的撤销恢复最初接入前的值，外部修改可从覆盖前备份找回；文件再次变化时需重新确认。修正 `status` 和 `/api/v1/runtime` 的 Claude Base URL，统一使用不带 `/v1` 的地址。Codex 配置的 provider 分隔注释前增加空行。
- 新增 `cabletidy restart` 和 `cabletidy update [<version|tag>]`。更新默认使用 `latest`，支持 `--check`、`--registry` 和 `--yes`，只更新当前全局 npm 前缀；Linux / macOS 更新后询问是否重启，Windows 先确认停止并等待原进程退出。配置损坏不影响更新状态探测。

## 管理接口与文件兼容性

- `config.json` 版本由 `2` 升为 `3`，`bindings` 更名为 `cables`；旧配置自动转换，保留线路 ID、上游凭据、模型设置和已有 Claude Code 接管记录。后续保存使用新字段，同时包含新旧字段的配置须先修正。新版配置不保证能被旧版读取。
- 导出接口由 `POST /api/v1/config/export` 改为 `POST /api/v1/cables/export`，选择字段由 `bindingIds` 改为 `cableIds`；导入接口由 `POST /api/v1/config/import` 改为 `POST /api/v1/cables/import`。其他管理请求中的 `bindingId` 改为 `cableId`，`status` 的线路列表为 `cables`。旧字段返回 `422 renamed_request_field`，外部脚本必须更新。
- 新导出文件标识为 `cabletidy.cables`，文件版本仍为 `1`，内部配置版本为 `3`；旧 `cabletidy.configuration-suites` 文件仍可导入。同时包含 `bindings` 和 `cables` 的文件拒绝导入，不部分写入。默认导出移除上游 URL 的用户名、密码、查询参数和片段，依赖查询参数的地址需导入后补齐；含凭据导出包含明文秘密。
- 服务设置保存在 `config.json.audit`，`retentionDays` 为天数、`budgetBytes` 为字节数，`null` 表示该项不限，不随线路导入导出。新建配置或缺少上限字段时使用 5 GiB；已有显式上限（包括 128 MiB）和“不限”保持原值。
- 审计 API 调用方需兼容 `inspectionStatus: limited`，并将 `legacyFindingCount` 与新增 / 历史风险计数分开处理。历史折叠和检测复用从新记录开始生效，旧正文及风险证据继续可查。

## 安装要求

- npm 安装支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。包自带原生程序，没有 npm 运行时依赖，安装不需要 Rust，也不下载额外二进制。
- 完整发行包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64。原生程序可脱离 Node.js 独立运行；源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。
- Codex 可选模型设置依赖本机支持 `debug models --bundled` 的 Codex CLI，纯透传不依赖该目录；Windows 查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 安装与升级

1. 用旧版 `cabletidy stop` 停止服务，确认退出后备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。从 `0.2.0` 升级须先按原终端 Ctrl+C 或通过原进程管理器停止，另见 [0.3.0 升级说明](0.3.0.md) 的旧目录锁迁移步骤。不要删除或替换新版持久的普通 `daemon.lock` 文件。
2. `0.4.0` 审计数据库保留敏感原文，可能包含认证信息、对话及工具内容；数据库、备份和含凭据导出应按敏感数据保管。旧版已脱敏记录不会恢复为原文。
3. 确认 npm 已发布正式包后安装并启动：

```bash
npm view cabletidy@0.4.0 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.4.0 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.4.0) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后执行 `npm install -g /absolute/path/package.tgz`。GitHub Release 与 npm 独立发布，是否可从 npm 安装以 registry 查询为准。正式包发布后，默认安装与 `cabletidy update` 使用的 `latest` 指向 `0.4.0`。

从 rc.6 升级继续沿用数据及客户端配置，不需要重新应用。从 `0.3.0` 或更早候选版升级也继续沿用 `config.json`、`secrets.json` 和审计数据库，启动时迁移旧字段及审计结构。名称变化不会改变线路 ID 或本地 URL，无需因此重新应用客户端；重命名线路、修改模型设置或导入新线路后仍须按需应用。若曾把旧 `status` 输出中带 `/v1` 的 Claude URL 手工写入客户端，需改成管理台提供的不带 `/v1` 地址，或重新应用后重启 Claude Code。Codex 注释空行在下次主动应用时更新，启动不会改写客户端文件。

启动后核对线路、模型映射、客户端接管状态、审计记录和服务设置。希望已有配置使用新默认容量时，在“设置”中将上限改为 5120 MiB 并保存；容量按需使用，不预占 5 GiB。外部管理脚本按上节更新接口和字段。

已支持 `update` 的版本可执行 `cabletidy update 0.4.0`，按提示重启。非交互终端默认拒绝启停确认，自动更新并重启需显式传入 `--yes`。源码、局部安装、npx 和独立原生程序须按原方式更新。

## 已知限制与恢复

- 安全审计仍为“仅记录”，不阻断操作、不额外调用模型，也不确认工具真实执行结果。无风险发现、检查复用或“已检查”均不表示已证明安全；会话和上下文标识来自客户端，无法可靠匹配的历史保守展开。
- 每条请求独立保存完整正文，不做正文去重、无关会话之间的缓存共享或响应到请求的跨阶段复用。旧记录不补造历史关联或阴性检测证明。
- 存储上限是审计容量预算，仍在处理的记录或读事务占用 WAL 时可能暂时超出上限；为状态与风险写入保留空间后，实际留存量可能低于上限。两项均不限时需自行监控磁盘。数据库或队列不可用时代理继续工作，页面显示检查失败、覆盖有限或存储缺口；设置不能恢复已清理记录。
- 线路删除不会自动恢复客户端文件，删除当前使用的线路前应先切换或撤销接入。含凭据导出、数据库及备份需妥善保管。
- 数据目录应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享锁协调；不包含开机自启或崩溃自动重启。
- 恢复旧版前先停止当前服务并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据与客户端配置备份。不要直接让旧版读取迁移后的配置或审计数据，也不要同时运行新旧 daemon。
