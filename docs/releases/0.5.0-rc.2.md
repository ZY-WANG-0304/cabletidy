# CableTidy 0.5.0-rc.2

这是 `0.5.0` 的第二个候选版本，基于合入 [PR #64](https://github.com/ZY-WANG-0304/cabletidy/pull/64) 后的 `origin/main`（`e189666c753ab65041b2df17cac4256d66cddff6`）。以下汇总相对 `0.5.0-rc.1` 的变化；相对稳定版 `0.4.0` 的此前变化见 [0.5.0-rc.1 发布说明](0.5.0-rc.1.md)。候选包发布到 npm `next`，`latest` 保持 `0.4.0`。

## 新增与改进

- 新增会话凭据保护。在“设置 → 凭据保护”开启全局默认，也可按线路选择沿用全局、启用或关闭；默认关闭，保存后立即生效。发送模型上下文前，将识别出的真实 Key / Token 等凭据替换为随机占位符，响应返回客户端前还原。同一入口、协议和会话内复用映射，每个新请求续期；默认闲置有效期为 1 小时，可设为 60 秒至 30 天。没有可识别会话标识时按单条请求隔离。见 [PR #64](https://github.com/ZY-WANG-0304/cabletidy/pull/64) 和 [凭据保护说明](../credential-protection.md)。
- 保护支持 Responses / Messages JSON 请求、普通 JSON 与 UTF-8 文本错误响应、嵌套 JSON 工具参数及常见 SSE 文本和工具事件。覆盖本地已保存凭据、常见 API Key、GitHub Token、AWS 凭据、JWT、私钥，以及凭据字段、赋值、Bearer、Cookie 和 URL 认证参数；保留工具 Schema 的普通定义语义，并处理重复 JSON 键、转义和初始 SSE 内容。附加请求头、上游 URL、查询参数与模型名若包含无法安全保护的凭据，发送前拒绝请求；上游身份认证继续使用真实 API Key。
- 会话轨迹在发生实际替换或还原时显示小钥匙，详情新增“凭据保护”页签，分别统计不同凭据数、请求替换次数和响应还原次数。支持原文预览与复制、映射新建 / 复用、续期时间、未使用历史映射折叠及原文位置弹出框。请求、响应和原始内容保留真实原文，保护位置使用青绿色高亮，与风险高亮叠加；明确区分未启用、零次操作、保护失败及证据不可用。
- 修复 `update` 完成提示：包安装成功后先明确报告已更新版本，并说明服务是否需要重启或启动；不再把已完成的更新显示为仍在进行。见 [PR #63](https://github.com/ZY-WANG-0304/cabletidy/pull/63)。
- 沿用上一候选版的独立临时目录设置、XDG 控制 socket、轨迹概览坐标轴与横向滚动，以及 Web 配置与审计领域逻辑迁移到 Rust。

## 配置与运行兼容性

- `config.json` 版本继续为 `3`。新增全局 `credentialProtection`（`enabled`、`mappingTtlSeconds`）及 `virtualProviders` 中每条线路可选的 `credentialProtection` 布尔覆盖。旧配置缺少字段时关闭保护；删除线路覆盖恢复继承。线路导入导出保留线路覆盖，全局设置不随线路导入导出。
- 已有线路 ID、本地 URL、上游密钥、审计设置及客户端配置继续沿用，无需因本次升级重新应用客户端。临时目录权限、长度与启动检查沿用上一候选版，详见 [0.5.0-rc.1 配置与运行兼容性](0.5.0-rc.1.md#配置与运行兼容性)。
- 运行时映射只驻留内存，进程重启清空；闲置过期后新请求建立新映射，仍在执行的旧请求保有原映射用于还原。历史审计不会重新激活运行时映射，已过期或重启后的服务端历史引用可能无法还原旧占位符。
- 本地审计仍保存真实凭据原文及映射证据，跟随原有保留周期与容量清理；运行时过期不会删除历史证据。数据库、数据目录与备份应沿用原有私有权限管理。

## 安装与升级

支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。完整 npm 包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64 原生程序；安装不需要 Rust，也不下载额外二进制。源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。

1. 用旧版 `cabletidy stop` 停止服务并确认退出，备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。从 `0.2.0` 升级须先通过原终端 Ctrl+C 或原进程管理器停止，另见 [0.3.0 升级说明](0.3.0.md)。
2. 确认 npm 已提供候选版本后安装并启动：

```bash
npm view cabletidy@0.5.0-rc.2 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.5.0-rc.2 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.5.0-rc.2) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后安装该 tarball。GitHub Release 与 npm 独立发布，npm 可用性以 registry 查询为准。

已支持 `update` 的版本可执行 `cabletidy update 0.5.0-rc.2`，按提示重启；`cabletidy update next --check` 检查候选版，`cabletidy update next` 安装。无参数更新继续使用稳定版 `latest`。启动后核对线路、客户端接管状态、审计记录及设置；按需开启凭据保护并检查请求替换、响应还原和原文定位。

## 已知限制与恢复

本版本为候选版。凭据保护与“仅记录”的风险审计相互独立：风险规则不触发阻断，启用的凭据保护在无法安全替换时返回 `422 credential_protection_failed`，不会退回明文转发；响应无法安全还原时终止响应并记录失败。保护不能承诺识别任意编码、二进制、图片、加密内容或模型改写后的占位符，服务器地址不做替换。

签名、思考和加密字段不修改，含需替换或还原的凭据时按保护失败处理。JSON 字符串嵌套最多 4 层，超出时拒绝转发。流式 JSON 工具参数，以及忽略前导空白后以 `{` 或 `[` 开头的文本，需要收齐通道后验证和还原，因此可能延迟到通道结束才输出；普通文本继续增量返回。运行时映射、暂存正文与证据仍受共享预算约束。

恢复旧版前停止候选版并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。旧版本不保证支持新增保护设置或证据；不要同时运行新旧 daemon，也不要让旧版直接读取已迁移数据来代替备份恢复。

## 发布与验收

发布提交执行版本一致性、格式、严格 Clippy、Rust / JavaScript 测试及安装冒烟验证。`v0.5.0-rc.2` 的 tag 工作流执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台构建和最终完整包安装验证；产物以成功工作流及 `release.json` 中的版本、提交、ref、运行 ID、SHA-256 和 integrity 为依据。

凭据保护自动化测试覆盖同会话复用、并发、闲置续期与过期、活跃旧请求还原、跨会话隔离、嵌套 JSON、SSE 分片及初始内容、保护失败前不联系上游，以及重启后的原文和高亮。浏览器验收脚本覆盖桌面和手机上的设置、页签、统计、复制、原文弹出框与高亮。

GitHub Pre-release 在工作流成功后自动创建并附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 与标签，并在隔离缓存和数据目录中从官方源验证安装、版本、管理台、停止和重启。

真实 Codex / Claude 上游接入、旧版升级与恢复、长期留存与磁盘压力、长会话服务端历史引用，以及 Windows 真实终端 Ctrl+C 与交互更新没有本候选版的新增人工验收记录。完整范围见 [维护者发布流程](../release-process.md)。
