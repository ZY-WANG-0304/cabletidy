# CableTidy 0.4.0-rc.2

这是 `0.4.0` 的第二个候选版本，基于合入 [PR #34](https://github.com/ZY-WANG-0304/cabletidy/pull/34) 后的 `main`（`66264b8`）。以下汇总相对 `0.4.0-rc.1` 的变化；首个候选版功能见 [0.4.0-rc.1 发布说明](0.4.0-rc.1.md)。候选包发布到 npm `next`，`latest` 保持稳定版 `0.3.0`。

## 新增与修复

- 审计概览完整展示 Codex Responses 与 Claude Messages 请求上下文：系统提示词、开发者指令、每条用户输入、历史模型消息、工具调用与结果、思考及历史引用，工具定义单独折叠。按原始顺序分页，每组最多 40 项，完整展示当前页文本、参数与结果，支持跨页工具关联；缺失或重复标识明确提示。见 [PR #34](https://github.com/ZY-WANG-0304/cabletidy/pull/34)、[Codex 请求概览](../codex-request-overview.md)及 [Claude 请求概览](../claude-request-overview.md)。
- 每项提供“查看此项原文”，按保留正文的精确字节范围加载、滚动和聚焦；长中文及 emoji 内容后的条目也可定位。原文导航与风险范围分开，保留已有敏感内容高亮，不把整项内容标为风险。
- 请求概览在独立的只读 SQLite 连接和有界队列中解析，支持取消、索引复用及分页，不阻塞审计读写队列，也不改变代理载荷。旧记录可直接生成概览；正文缺口、中断及旧快照的不完整状态仍明确展示，不因 JSON 可解析而标为完整。
- 修复审计原始内容与检测快照展开后未加载，以及流式导航期间正文加载结果丢失的问题。见 [PR #31](https://github.com/ZY-WANG-0304/cabletidy/pull/31)。
- 修复 Codex / Claude 会话归组，识别各客户端的会话头并保留合法回退；已有可恢复标识的记录在启动时补齐归组，按配置与协议保持隔离，无标识记录仍独立展示。见 [PR #32](https://github.com/ZY-WANG-0304/cabletidy/pull/32)。
- Claude 模型选择保存后明确提示需要重新“应用到 Claude Code”才能生效；优化会话轨迹概览、请求与风险图例及耗时占比说明。见 [PR #33](https://github.com/ZY-WANG-0304/cabletidy/pull/33)。

## 安装要求

- 支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。npm 包自带原生程序，没有 npm 运行时依赖，安装不需要 Rust，也不下载额外二进制。
- 完整发行包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64。源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。
- Codex 可选模型设置仍依赖本机支持 `debug models --bundled` 的 Codex CLI；纯透传不依赖该目录。Windows 的模型目录查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 安装与升级

1. 使用旧版 `cabletidy stop` 停止服务，确认退出后备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。
2. **本版本新审计记录会保留敏感原文，不再在落盘前替换凭据。** 审计数据库及其备份可能包含认证信息、对话和工具内容，应按敏感数据保管。旧版已脱敏的记录不会恢复为原文。
3. 确认 npm 已发布候选包后安装并启动：

```bash
npm view cabletidy@0.4.0-rc.2 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.4.0-rc.2 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.4.0-rc.2) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后执行 `npm install -g /absolute/path/package.tgz`。GitHub Release 与 npm 独立发布，是否可从 npm 安装以 registry 查询结果为准。

从 `0.4.0-rc.1` 或 `0.3.0` 升级继续沿用 `config.json`、`secrets.json` 及已有审计数据库，无需因本次升级重新应用客户端配置。启动后核对已有配置、模型映射及审计记录。从 `0.2.0` 或早期 `0.3.0` 候选版升级时，还需遵循 [0.3.0 发布说明](0.3.0.md) 中的停止服务、旧目录锁迁移及客户端配置步骤。不要删除或替换新版持久的普通 `daemon.lock` 文件。

## 已知限制与恢复

- 安全审计仍为“仅记录”，不阻断操作，不额外调用模型，也不确认工具真实执行结果。会话标识由客户端报告；无标识的历史记录不根据时间或内容猜测归组。
- 审计默认保留 30 天、容量预算 128 MiB，容量压力下可能提前清理。数据库或队列不可用时代理继续工作，页面显示检查失败、覆盖不足或存储缺口；无风险发现不等于已证明安全。
- 配置删除不会自动恢复客户端文件。删除当前使用的配置前，应先切换或撤销客户端接入。
- 数据目录应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享锁协调；不包含开机自启或崩溃自动重启。
- 恢复旧版前先用候选版 `stop` 停止并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。不要直接让旧版读取已更新的数据代替恢复演练，也不要同时运行新旧 daemon。

## 发布与验收

发布准备期间修正 Windows 并行 CI 下的测试时间预算：队列隔离测试在概览接收端持续阻塞时验证审计读写完成，以有界超时防止死锁；代理契约测试放宽本地请求超时。生产逻辑不变。

发布提交需通过版本一致性、格式、严格 Clippy、Rust / JavaScript 测试及安装冒烟验证。`v0.4.0-rc.2` 的 tag 工作流重新执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台构建和最终完整包安装验证；以该 tag 的成功运行及 `release.json` 记录的提交、ref、运行 ID 和摘要为产物依据。

GitHub Pre-release 在工作流成功后自动创建并附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 与标签，并使用隔离缓存和数据目录验证安装、版本、管理台、停止及重启。

请求概览已有 Rust、HTTP、页面与桌面 / 手机浏览器验证记录，详见上述请求概览文档。本候选版的真实 Codex / Claude 上游接入、从旧版升级与恢复、配置删除后的客户端切换以及 Windows 真实终端 Ctrl+C 尚待人工验收；此前版本的人工结果不能替代本候选版验收。完整范围见 [维护者发布流程](../release-process.md)。
