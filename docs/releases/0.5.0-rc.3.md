# CableTidy 0.5.0-rc.3

这是 `0.5.0` 的第三个候选版本，基于 `origin/main`（`e098cce77a176c7fb9912759fc1d45eec429df11`）。以下汇总相对 `0.5.0-rc.2` 源码 tag 的变化；此前候选版的会话凭据保护、流式响应还原、审计原文高亮及其他变化见 [0.5.0-rc.2 发布说明](0.5.0-rc.2.md) 和 [0.5.0-rc.1 发布说明](0.5.0-rc.1.md)。候选包发布到 npm `next`，`latest` 保持稳定版 `0.4.0`。

## 新增与修复

- 凭据保护统一到“设置 → 凭据保护”：总开关开启且线路选中时才执行保护，支持全选、逐条选择和有效期单位换算，一次保存立即生效。关闭总开关会禁用所有线路的保护并保留选择，重新开启后恢复；新增线路默认选中。线路详情页不再单独提供保护设置。见 [PR #69](https://github.com/ZY-WANG-0304/cabletidy/pull/69)。
- 审计与保护共享原文凭据候选、证据及字节位置，检测事实与实际替换结果分别记录。风险与保护详情展示候选来源、匹配策略、低置信候选和未替换原因，保护关闭时仍执行检测和审计；旧记录缺少证据时显示“未记录”。见 [PR #67](https://github.com/ZY-WANG-0304/cabletidy/pull/67)。
- 修复源码、类型声明、变量引用、动态表达式、普通 Cookie、JWT 外形及已遮罩文本中的误判；完善凭据字段名称、类型注解后固定字面量、认证 Cookie、嵌套 JSON 与转义定位。工具 grammar、Schema 约束、协议标识及其他不能安全修改的结构含真实强凭据时拒绝转发。短值和低熵会话凭据按完整值匹配，较长自发现凭据按单位边界匹配，减少对普通正文和标识符的污染。完整规则与限制见 [凭据保护说明](../credential-protection.md)。
- 新增源码命令 `npm run preview`（兼容拼写 `npm run perview`），从最新 `origin/main` 隔离构建并安装当前平台快照。快照版本例如 `0.5.0-preview.261019.ge098cce`，包含 UTC 短日期与 7 位提交 SHA，完整提交保存在构建元数据中；运行服务在安装前停止，安装完成后按提示重启。见 [PR #68](https://github.com/ZY-WANG-0304/cabletidy/pull/68) 和 [PR #70](https://github.com/ZY-WANG-0304/cabletidy/pull/70)。
- 附带历史凭据检测复用的测试构建实验及性能记录。正式安装包继续完整检测，实验缓存没有默认启用；结果与适用边界见 [实验报告](../research/credential-cache-experiment/report.md)。

## 配置与运行兼容性

`config.json` 版本继续为 `3`，已有线路 ID、本地 URL、上游密钥、审计设置及客户端配置继续沿用，无需因本次升级重新应用客户端。

凭据保护开关语义有所变化：全局 `credentialProtection.enabled` 现在是总开关，线路 `credentialProtection` 表示是否选中，缺少线路字段时默认选中。旧配置中“全局关闭、线路启用”升级后不再执行保护；需要保护时在设置页开启总开关并核对选中的线路。共用同一 Virtual Provider 入口的线路共用选择状态。线路导入导出保留选择，全局设置不随线路导入导出。

闲置有效期仍默认 1 小时，可设为 60 秒至 30 天，每个新请求续期。运行时映射只驻留内存，重启清空；过期后的新请求建立新映射，活跃旧请求保有其映射用于还原。规则版本升级后，旧版本映射只用于响应还原，不再作为新检测依据。历史审计保留原规则版本与结论。

本地审计仍保存真实凭据原文及映射证据，跟随原有保留周期和容量清理。运行时映射过期不会删除历史证据，历史审计也不会重新激活映射。数据库、数据目录与备份继续按原有私有权限管理。

## 安装与升级

支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。完整 npm 包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64 原生程序；安装不需要 Rust，也不下载额外二进制。源码构建及 `npm run preview` 需要 Rust 1.95 或更新版本与系统 C 工具链。

1. 用旧版 `cabletidy stop` 停止服务并确认退出，备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。从 `0.2.0` 升级须先通过原终端 Ctrl+C 或原进程管理器停止，另见 [0.3.0 升级说明](0.3.0.md)。
2. 查询并安装候选版本后启动：

```bash
npm view cabletidy@0.5.0-rc.3 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.5.0-rc.3 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

已支持 `update` 的版本也可执行 `cabletidy update 0.5.0-rc.3`，按提示重启；`cabletidy update next --check` 检查候选版，`cabletidy update next` 安装。无参数更新继续使用稳定版 `latest`。启动后核对线路、客户端接管状态和审计记录，尤其检查凭据保护总开关与线路选择，再验证请求替换、响应还原及原文定位。

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.5.0-rc.3) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后安装该 tarball。GitHub Release 与 npm 独立发布，npm 可用性以 registry 查询为准。

## 已知限制与恢复

本版本为候选版。风险审计与凭据保护独立；风险规则仅记录，启用的保护在无法安全替换时返回 `422 credential_protection_failed`，响应无法安全还原时终止响应并记录失败。上游身份认证继续使用真实 API Key，服务器地址仅审计、不替换。保护不能承诺识别任意编码、二进制、图片、加密内容或模型改写后的占位符。

签名、思考和加密字段不修改，含需替换或还原的凭据时按保护失败处理。嵌套 JSON 字符串最多处理 4 层；流式 JSON 工具参数及以 `{` 或 `[` 开头的 JSON 文本需要收齐通道后验证和还原，可能延迟到通道结束才输出；普通文本继续增量返回。原文、映射与暂存正文仍受共享资源预算约束。

检测及缓存实验的合成样本独立性、保护开关 p95 门槛尚未全面达标；报告不能作为生产精确率、召回率或延迟承诺。测试专用历史缓存未进入普通发行构建。

恢复旧版前停止候选版并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据和客户端配置备份。旧版本不保证支持新增证据或相同开关语义；不要同时运行新旧 daemon，也不要让旧版直接读取当前数据来代替备份恢复。

## 发布与验收

发布提交执行版本一致性、格式、严格 Clippy、Rust / JavaScript 测试与安装冒烟验证。`v0.5.0-rc.3` 的 tag 工作流执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台原生构建，以及最终完整 tarball 的安装验证；产物来源以成功工作流和 `release.json` 中的版本、提交、ref、运行 ID、SHA-256 与 integrity 为依据。

新增回归覆盖审计与保护同候选证据、源码及协议结构边界、会话学习与短值污染、总开关和线路选择、设置保存与重启保留，以及快照版本、构建元数据和安装流程。此前候选版的 JSON / SSE 还原、失败前不联系上游、审计持久化及服务生命周期测试继续执行。

GitHub Pre-release 在工作流成功后自动创建，附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 和标签，并在隔离缓存与数据目录中从官方源验证安装、版本、管理台、停止及重启。

真实 Codex / Claude 上游接入、旧版数据升级与恢复、长期留存和磁盘压力，以及 Windows 真实终端 Ctrl+C 与交互更新没有本候选版的新增人工验收记录。完整流程见 [维护者发布流程](../release-process.md)。
