# CableTidy 0.4.0-rc.5

这是 `0.4.0` 的第五个候选版本，基于合入 [PR #47](https://github.com/ZY-WANG-0304/cabletidy/pull/47)、[PR #48](https://github.com/ZY-WANG-0304/cabletidy/pull/48) 和 [PR #49](https://github.com/ZY-WANG-0304/cabletidy/pull/49) 后的 `origin/main`（`a152439`）。以下汇总相对 `0.4.0-rc.4` 的变化；之前的功能见 [0.4.0-rc.4 发布说明](0.4.0-rc.4.md)。候选包发布到 npm `next`，`latest` 保持稳定版 `0.3.0`。

## 新增与修复

- 管理台新增顶级“设置”页面，管理对全部配置套装生效的审计保存周期和存储上限。默认保留 30 天、容量预算 128 MiB；有限值分别至少 1 天和 16 MiB，两项均可独立选择“不限”。保存后立即生效并在重启后继续使用，复用配置提交、校验、修订冲突检查与备份流程。页面保护未保存草稿，按设置的实际语义合并并发修改，同一项冲突时保留草稿并暂停保存。见 [PR #48](https://github.com/ZY-WANG-0304/cabletidy/pull/48)；[桌面预览](../screenshots/service-settings-desktop.png) · [手机预览](../screenshots/service-settings-mobile.png)。
- 审计时间和容量策略独立生效，两项均不限时停止这两种自动清理，并解除正文存储预算与 SQLite 固定页数限制。降低上限时优先清理已完成记录及其关联正文、风险和缓存，保留仍在接收或检查的记录；既有记录仍可写入结束状态与正文清单。容量判断依据有效页面占用，删除历史后连续分批回收空闲页；读事务占用 WAL 或 checkpoint 阻塞时延后回收，避免因文件暂时不能压缩而额外删除历史。
- 旧版本审计记录缺少可靠的新增 / 历史风险分类，改为显示“未发现风险”或“风险 N 项”；新记录继续区分新增风险和历史风险。请求行、轨迹导航、图例及会话汇总使用一致口径，会话 API 新增 `legacyFindingCount`，分别统计旧记录风险、新增风险和历史关联。不回填历史关系或改写原始风险数量。见 [PR #47](https://github.com/ZY-WANG-0304/cabletidy/pull/47)。
- 修正 CLI `status`、默认状态输出及 `/api/v1/runtime` 中 Claude Code 的 Base URL，使用不带 `/v1` 的本地地址，与管理台和生成的 `ANTHROPIC_BASE_URL` 一致，避免复制状态地址后产生 `/v1/v1/messages` 请求。Codex 地址继续带 `/v1`。见 [PR #49](https://github.com/ZY-WANG-0304/cabletidy/pull/49)。

## 安装要求

- 支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。npm 包自带原生程序，没有 npm 运行时依赖，安装不需要 Rust，也不下载额外二进制。
- 完整发行包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64。源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。
- Codex 可选模型设置依赖本机支持 `debug models --bundled` 的 Codex CLI；纯透传不依赖该目录。Windows 的模型目录查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 安装与升级

1. 用旧版 `cabletidy stop` 停止服务，确认退出后备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。
2. `0.4.0` 候选版审计数据库保留敏感原文，可能包含认证信息、对话及工具内容；备份和包含凭据的导出文件应按敏感数据保管。旧版已脱敏记录不会恢复为原文。
3. 确认 npm 已发布候选包后安装并启动：

```bash
npm view cabletidy@0.4.0-rc.5 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.4.0-rc.5 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.4.0-rc.5) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后执行 `npm install -g /absolute/path/package.tgz`。GitHub Release 与 npm 独立发布，是否可从 npm 安装以 registry 查询结果为准。

从 `0.4.0-rc.4`、更早的 `0.4.0` 候选版或 `0.3.0` 升级继续沿用 `config.json`、`secrets.json` 及已有审计数据库。旧配置缺少 `audit` 字段时采用默认值；后续保存时持久化 `retentionDays`（天数）和 `budgetBytes`（字节数），`null` 表示对应限制关闭。这些服务设置不随配置套装导出或导入。

无需因本次升级重新应用 CableTidy 生成的客户端配置。如果曾手工把状态输出中的 Claude URL（末尾带 `/v1`）复制到客户端，请核对并改为管理台提供的不带 `/v1` 的地址，或重新应用配置后重启 Claude Code。查询审计 API 的外部工具应将 `legacyFindingCount` 与新增 / 历史计数分开处理。启动后核对已有配置、模型映射、审计记录和设置页面；缩短保存周期或降低存储上限可能立即清理历史，单独关闭一项限制时另一项仍可能清理记录。

从 `0.2.0` 或早期 `0.3.0` 候选版升级时，还需遵循 [0.3.0 发布说明](0.3.0.md) 中的停止服务、旧目录锁迁移及客户端配置步骤。不要删除或替换新版持久的普通 `daemon.lock` 文件。

已支持 `update` 的版本可执行 `cabletidy update 0.4.0-rc.5`，按提示重启服务。`cabletidy update next --check` 检查后续候选版，`cabletidy update next` 安装；无参数的 `update` 使用稳定版 `latest`，当前候选版高于稳定版时不会自动降级。非交互终端默认拒绝启停确认，自动更新并重启需显式传入 `--yes`。

## 已知限制与恢复

- 安全审计仍为“仅记录”，不阻断操作，不额外调用模型，也不确认工具真实执行结果。无风险发现、检查复用或“已检查”均不表示已证明安全；会话与上下文标识来自客户端，无法可靠匹配的历史保守展开。
- 每条请求继续独立保存完整正文，尚不做正文存储去重、无关会话之间的缓存共享或响应到请求的跨阶段复用。旧记录不补造历史关联或阴性缓存。
- 存储上限是审计容量预算，仍在处理的记录或读事务占用的 WAL 会延后回收，磁盘占用可能暂时超出上限；为写入状态和风险信息保留空间后，实际留存量可能低于上限。两项均不限时应自行监控磁盘。数据库或队列不可用时代理继续工作，页面显示检查失败、覆盖有限或存储缺口；设置不会恢复已经清理的记录。
- 默认不含凭据的配置导出会移除上游 URL 中的用户名、密码、查询参数与片段；依赖查询参数的地址需在导入后补齐。导出不携带客户端文件、应用与恢复记录、审计日志和机器设置；配置删除不会自动恢复客户端文件。
- 数据目录应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享锁协调；不包含开机自启或崩溃自动重启。原生程序独立运行时需手动替换二进制，`update` 仅适用于全局 npm 安装。
- 恢复旧版前先停止候选版并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。不要直接让旧版读取已更新的数据代替恢复演练，也不要同时运行新旧 daemon。

## 发布与验收

发布提交需通过版本一致性、格式、严格 Clippy、Rust / JavaScript 测试及安装冒烟验证。`v0.4.0-rc.5` 的 tag 工作流执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台构建和最终完整包安装验证；以该 tag 的成功运行及 `release.json` 记录的提交、ref、运行 ID 和摘要为产物依据。

GitHub Pre-release 在工作流成功后自动创建并附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 与标签，并使用隔离缓存和数据目录验证安装、版本、管理台、停止及重启。

本候选版的真实 Codex / Claude 上游接入、旧版升级与恢复、长期审计留存与磁盘压力、长会话及 fork / side 历史匹配，以及 Windows 真实终端 Ctrl+C 与交互更新仍需人工验收；自动化模拟测试及此前版本的人工结果不能替代本候选版验收。完整范围见 [维护者发布流程](../release-process.md)。
