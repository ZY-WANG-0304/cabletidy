# CableTidy 0.4.0-rc.3

这是 `0.4.0` 的第三个候选版本，基于合入 [PR #40](https://github.com/ZY-WANG-0304/cabletidy/pull/40) 后的 `main`（`cf7ce42`）。以下汇总相对 `0.4.0-rc.2` 的变化；之前的功能见 [0.4.0-rc.2 发布说明](0.4.0-rc.2.md)。候选包发布到 npm `next`，`latest` 保持稳定版 `0.3.0`。

## 新增与修复

- 审计详情拆分“请求内容”和“响应内容”页签，完整展示 Codex Responses / Claude Messages 的本轮模型文本、推理与思考、工具调用及服务端结果；提供分类统计、独立分页和精确原文定位。流式增量与最终输出合并去重，保留分片、签名和自由文本工具输入，缺失或中断明确提示。见 [PR #36](https://github.com/ZY-WANG-0304/cabletidy/pull/36)、[Codex 响应内容概览](../codex-response-overview.md)和 [Claude 响应内容概览](../claude-response-overview.md)。
- 会话风险可跳转到请求或响应内容中的对应位置，自动加载所需分页；普通浏览时，请求内容、响应内容和原始内容也持续高亮风险位置。修复筛选后的工具参数风险匹配、风险导航状态和初始响应证据保留。见 [PR #37](https://github.com/ZY-WANG-0304/cabletidy/pull/37)。
- 收敛凭据误报：按前缀、长度和熵判断，自然语言词、公开 SSH 地址及纯数字遮罩不再误判；尖括号占位符须完整闭合。新增服务器地址检测，覆盖 IPv4、IPv6 及常见编码形式，区分公网和内网；排除版本号、MAC 地址、时间戳及常见代码路径。见 [PR #38](https://github.com/ZY-WANG-0304/cabletidy/pull/38)。
- 管理台支持配置套装导出、导入预览及同名配置的更新或新建。默认不导出认证凭据；可明确勾选携带明文密钥及完整上游 URL。导入时可选择使用或忽略文件凭据，保留仍被共享的本机连接与密钥；文件无效或修订冲突时不部分写入，不自动修改客户端文件。修复 Unicode 长名称和尾部分隔符导致的导入后缀问题。见 [PR #39](https://github.com/ZY-WANG-0304/cabletidy/pull/39)。
- 新增 `cabletidy restart`，正常排空并停止旧服务，再按原配置启动；未运行时直接启动，停止失败或被取消时不启动新服务。安装版默认后台运行，支持 `--foreground`。
- 新增 `cabletidy update [<version|tag>]`，默认检查并安装 `latest`，支持 `--check`、`--registry` 和 `--yes`；仅更新当前全局 npm 安装前缀。Linux / macOS 更新后询问是否重启，Windows 先确认停止并等待原进程退出，再安装并询问是否启动。配置损坏不影响状态探测，主机改名不影响退出等待；源码、局部安装或 npx 使用方式需按原方式更新。见 [PR #40](https://github.com/ZY-WANG-0304/cabletidy/pull/40)。

## 安装要求

- 支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。npm 包自带原生程序，没有 npm 运行时依赖，安装不需要 Rust，也不下载额外二进制。
- 完整发行包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64。源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。
- Codex 可选模型设置依赖本机支持 `debug models --bundled` 的 Codex CLI；纯透传不依赖该目录。Windows 的模型目录查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 安装与升级

1. 用旧版 `cabletidy stop` 停止服务，确认退出后备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。`0.4.0-rc.2` 及更早版本没有本次新增的 `update` 命令。
2. `0.4.0` 候选版审计数据库保留敏感原文，可能包含认证信息、对话及工具内容；备份和包含凭据的导出文件应按敏感数据保管。旧版已脱敏记录不会恢复为原文。
3. 确认 npm 已发布候选包后安装并启动：

```bash
npm view cabletidy@0.4.0-rc.3 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.4.0-rc.3 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.4.0-rc.3) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后执行 `npm install -g /absolute/path/package.tgz`。GitHub Release 与 npm 独立发布，是否可从 npm 安装以 registry 查询结果为准。

从 `0.4.0-rc.2`、`0.4.0-rc.1` 或 `0.3.0` 升级继续沿用 `config.json`、`secrets.json` 及已有审计数据库，无需因本次升级重新应用客户端配置。启动后核对已有配置、模型映射与审计记录；导入配置后的客户端应用需按需手动执行。从 `0.2.0` 或早期 `0.3.0` 候选版升级时，还需遵循 [0.3.0 发布说明](0.3.0.md) 中的停止服务、旧目录锁迁移及客户端配置步骤。不要删除或替换新版持久的普通 `daemon.lock` 文件。

安装本版本后可用 `cabletidy update next --check` 检查后续候选版本，或用 `cabletidy update next` 安装。无参数的 `update` 使用稳定版 `latest`，当前候选版高于稳定版时不会自动降级；显式指定版本或标签可以降级，但不能代替数据恢复。非交互终端默认拒绝启停确认，自动更新并重启需显式传入 `--yes`。

## 已知限制与恢复

- 安全审计仍为“仅记录”，不阻断操作，不额外调用模型，也不确认工具真实执行结果。无风险发现不等于已证明安全；会话标识由客户端报告，无标识记录不猜测归组。
- 审计默认保留 30 天、容量预算 128 MiB，容量压力下可能提前清理。数据库或队列不可用时代理继续工作，页面显示检查失败、覆盖不足或存储缺口。
- 默认不含凭据的配置导出会移除上游 URL 中的用户名、密码、查询参数与片段；依赖查询参数的地址需在导入后补齐。导出不携带客户端文件、应用与恢复记录、审计日志和机器设置；配置删除不会自动恢复客户端文件。
- 数据目录应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享锁协调；不包含开机自启或崩溃自动重启。原生程序独立运行时需手动替换二进制，`update` 仅适用于 npm 启动器。
- 恢复旧版前先停止候选版并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。不要直接让旧版读取已更新的数据代替恢复演练，也不要同时运行新旧 daemon。

## 发布与验收

发布提交需通过版本一致性、格式、严格 Clippy、Rust / JavaScript 测试及安装冒烟验证。`v0.4.0-rc.3` 的 tag 工作流执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台构建和最终完整包安装验证；以该 tag 的成功运行及 `release.json` 记录的提交、ref、运行 ID 和摘要为产物依据。

GitHub Pre-release 在工作流成功后自动创建并附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 与标签，并使用隔离缓存和数据目录验证安装、版本、管理台、停止及重启。

本候选版的真实 Codex / Claude 上游接入、旧版升级与恢复、配置删除后的客户端切换，以及 Windows 真实终端 Ctrl+C 与交互更新仍需人工验收；自动化模拟测试及此前版本的人工结果不能替代本候选版验收。完整范围见 [维护者发布流程](../release-process.md)。
