# CableTidy 0.4.0-rc.1

这是 `0.4.0` 的首个候选版本，基于合入 [PR #29](https://github.com/ZY-WANG-0304/cabletidy/pull/29) 后的 `main`（`4897fe5`）。以下汇总相对稳定版 `0.3.0` 的变化。候选包发布到 npm `next`，`latest` 保持 `0.3.0`。

## 新增与修复

- 配置列表和详情页支持确认后删除配置，同时清理不再使用的 provider、route、upstream 和凭据，保留其他配置共享的依赖。取消或提交失败时保留原配置和未保存输入。删除后对应接入地址停止服务，已写入 Codex / Claude 的配置需要另行切换或恢复。见 [PR #27](https://github.com/ZY-WANG-0304/cabletidy/pull/27)。
- 审计详情保留请求、响应及检测快照中的敏感原文，自动高亮凭据、认证头、Cookie、私钥等命中片段，支持点击风险定位、长正文分页、UTF-8 和跨流式分片检测。修复响应证据定位、检测快照展开及 JSON `null` 值触发凭据误报的问题。旧脱敏记录继续可读，已经替换的内容无法恢复；普通诊断事件继续脱敏。见 [PR #28](https://github.com/ZY-WANG-0304/cabletidy/pull/28)。
- 审计首页按客户端会话标识归组，并按配置入口及协议隔离；无标识的请求独立展示。会话内按请求顺序展示轨迹，支持连续加载、摘要与模型搜索、风险筛选、耗时占比和客户端模型到上游模型的映射。风险筛选命中会话后保留全部已留存上下文，旧请求 UUID 链接仍可定位对应记录。见 [PR #29](https://github.com/ZY-WANG-0304/cabletidy/pull/29)。
- 会话详情支持概览、风险和原始内容切换；刷新、追加及失败重试保留请求选择与滚动位置。刷新期间切换请求后，过期结果不会覆盖最新选择；模型输出摘要不再混入工具参数。
- CableTidy 自身的配置提交、启停、客户端应用和恢复退出安全审计范围；历史配置操作不再通过审计接口展示，仍按原保留策略过期。Agent 请求、响应、内容检测及存储缺口继续记录。

## 安装要求

- 支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24。npm 包自带原生程序，没有 npm 运行时依赖，安装不需要 Rust，也不下载额外二进制。
- 完整发行包包含 Linux x64 / arm64（musl）、macOS x64 / arm64 和 Windows x64。源码构建需要 Rust 1.95 或更新版本及系统 C 工具链。
- Codex 可选模型设置仍依赖本机支持 `debug models --bundled` 的 Codex CLI；纯透传不依赖该目录。Windows 的模型目录查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 安装与升级

1. 使用旧版 `cabletidy stop` 停止服务，确认退出后备份完整 CableTidy 数据目录（默认 `~/.cabletidy`）及 Codex / Claude 配置目录。
2. **本版本新审计记录会保留敏感原文，不再在落盘前替换凭据。** 审计数据库及其备份可能包含认证信息、对话和工具内容，应按敏感数据保管。旧版已脱敏的记录不会恢复为原文。
3. 确认 npm 已发布候选包后安装并启动：

```bash
npm view cabletidy@0.4.0-rc.1 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.4.0-rc.1 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

也可从 [GitHub Pre-release](https://github.com/ZY-WANG-0304/cabletidy/releases/tag/v0.4.0-rc.1) 下载 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要及来源后执行 `npm install -g /absolute/path/package.tgz`。GitHub Release 与 npm 独立发布，是否可从 npm 安装以 registry 查询结果为准。

从 `0.3.0` 升级继续沿用 `config.json`、`secrets.json` 及已有审计数据库，无需因本次升级重新应用客户端配置。启动后核对已有配置、模型映射及审计记录。从 `0.2.0` 或早期 `0.3.0` 候选版升级时，还需遵循 [0.3.0 发布说明](0.3.0.md) 中的停止服务、旧目录锁迁移及客户端配置步骤。不要删除或替换新版持久的普通 `daemon.lock` 文件。

## 已知限制与恢复

- 安全审计仍为“仅记录”，不阻断操作，不额外调用模型，也不确认工具真实执行结果。会话标识由客户端报告；无标识的历史记录不根据时间或内容猜测归组。
- 审计默认保留 30 天、容量预算 128 MiB，容量压力下可能提前清理。数据库或队列不可用时代理继续工作，页面显示检查失败、覆盖不足或存储缺口；无风险发现不等于已证明安全。
- 配置删除不会自动恢复客户端文件。删除当前使用的配置前，应先切换或撤销客户端接入。
- 数据目录应位于本地文件系统，不承诺 NFS / SMB 或跨机器共享锁协调；不包含开机自启或崩溃自动重启。
- 恢复旧版前先用候选版 `stop` 停止并确认退出，保留当前数据副本，再安装旧版本并恢复升级前的数据及客户端配置备份。不要直接让旧版读取已更新的数据代替恢复演练，也不要同时运行新旧 daemon。

## 发布与验收

发布提交需通过版本一致性、格式、严格 Clippy、Rust / JavaScript 测试及安装冒烟验证。`v0.4.0-rc.1` 的 tag 工作流重新执行 Linux、macOS、Windows × Node.js 22.13.0 / 24 六组检查、五平台构建和最终完整包安装验证；以该 tag 的成功运行及 `release.json` 记录的提交、ref、运行 ID 和摘要为产物依据。

GitHub Pre-release 在工作流成功后自动创建并附上完整包、摘要和提交信息；npm 使用同一份已验证的 tarball 发布到 `next`。发布后核对 registry integrity 与标签，并使用隔离缓存和数据目录验证安装、版本、管理台、停止及重启。

此次候选版的真实 Codex / Claude 上游接入、从 `0.3.0` 升级与恢复、配置删除后的客户端切换以及 Windows 真实终端 Ctrl+C 尚待人工验收；此前版本的人工结果不能替代本候选版验收。完整范围见 [维护者发布流程](../release-process.md)。
