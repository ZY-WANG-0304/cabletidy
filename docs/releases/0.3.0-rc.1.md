# CableTidy 0.3.0-rc.1

这是 `0.3.0` 的首个候选版本，变更范围为 `v0.2.0` 之后的 Rust 迁移、安全审计、后台运行、开发环境和发布流程更新。候选版用于升级与跨平台验收，不替代 npm 的稳定版 `latest`。

GitHub tag 为 `v0.3.0-rc.1`。tag 工作流通过后自动创建 Pre-release，附上完整五平台安装包和校验信息；npm 需要另外发布到 `next`。本说明不代表 GitHub 或 npm 产物已经可用。

## 新增与改进

- 服务端迁移到 Rust，Web 资源嵌入原生程序。npm 包保留 Node.js 薄启动器，自带五个平台二进制；安装不下载二进制、不编译 Rust，没有 npm 运行时依赖。
- 安装版 `cabletidy start` 在后台运行，管理接口就绪后返回地址和日志路径；新增 `cabletidy stop`，排空请求后退出。`start --foreground` 支持前台运行，源码入口继续前台运行。
- daemon 日志自动轮转，每个文件最多 10 MiB，保留三份历史日志。停止请求校验进程身份，支持取消等待，不直接向缓存 PID 强制发送终止信号。
- 管理台新增安全审计页面，按请求或操作查看风险、保留正文及上下文；支持分类筛选、风险定位和正文分页。凭据等内容在落盘前定向脱敏，长正文使用有界内存和加密临时暂存。
- `npm run dev` 使用独立的开发数据及客户端配置目录，支持 Rust / Web 文件变化后的重启。管理台显示软件版本，配置修订号单独展示。
- 发布流程核对四个版本文件与 tag，在同一提交上执行完整检查，验证五平台发行二进制及最终 tarball，并自动创建带摘要和提交信息的 GitHub Release。

## 安装要求

- npm 启动器支持 Node.js `^22.13.0 || >=24`，推荐 Node.js 24；用户安装不需要 Rust。独立原生二进制不需要 Node.js。
- 完整发行包支持 Linux x64 / arm64（musl）、macOS x64 / arm64、Windows x64。其他平台需自行源码构建。
- Codex 可选模型设置仍依赖本机支持 `debug models --bundled` 的 Codex CLI，纯透传不依赖该目录。Windows 的 Codex 目录查询需要允许 `Add-Type` 的系统 Windows PowerShell。

## 从 0.2.0 升级与试用

1. 在运行旧版的终端按 Ctrl+C，或通过原进程管理器停止旧服务。`0.2.0` 没有 `cabletidy stop` 命令。
2. 停止后备份完整数据目录（默认 `~/.cabletidy`）以及 Codex / Claude 配置目录。优先使用目录副本和隔离的测试客户端配置验收候选版。
3. 确认 npm 上该候选版本已发布后，指定版本安装：

```bash
npm view cabletidy@0.3.0-rc.1 version --registry=https://registry.npmjs.org/
npm install -g cabletidy@0.3.0-rc.1 --registry=https://registry.npmjs.org/
cabletidy --version
cabletidy start
cabletidy status
```

若 npm 尚未发布，可下载对应 GitHub Pre-release 的 `package.tgz`、`SHA256SUMS` 和 `release.json`，核对摘要后执行 `npm install -g /absolute/path/package.tgz`。提交 SHA、版本和构建信息在 `release.json` 中；不要将本地单平台测试包作为完整发行包。

已有 `config.json` 和 `secrets.json` 继续沿用，不要求转换为 TOML 或 OS keyring。安装本身不启动服务、不改写客户端配置。启动后核对保存的端口、上游和模型设置；仅在需要更新接入配置时主动预览并应用。更早版本使用独立代理端口的配置，需要重新应用客户端接入以更新地址。

新版后台启动后，关闭终端不会停止服务。使用 `cabletidy stop` 停止；它会等待已开始的请求排空，长请求可能延长等待。停止命令收到 Ctrl+C 时会说明停止请求是否已提交：提交后只取消客户端等待，daemon 继续退出。不提供开机自启或崩溃自动重启。

## 安全审计范围与数据

安全审计固定为“仅记录”，不会阻断操作或额外调用模型，也不确认客户端工具的真实执行结果。未知工具、图片、加密内容、规则未覆盖或资源不足时可能存在检查缺口；没有发现风险不表示已经证明安全。

数据目录新增 `audit.sqlite3`，默认保留 30 天、容量预算 128 MiB，容量压力下可能提前清理。正文会保留对话、输出和命令等内容；凭据定向脱敏不等于所有正文都不敏感。数据库或队列不可用时代理继续工作，管理台显示退化状态和缺口；强制退出可能丢失未提交记录。

## 验收状态

2026-10-02 在 Linux x64、Node.js 25.6.0、Rust 1.98.1 上完成以下本地验证：

- 四个版本文件和 `v0.3.0-rc.1` tag 一致性检查、Rust 格式检查及 Clippy 通过。
- `npm test` 通过 43 项 Rust 测试和 266 项 JavaScript 测试，含发布预演；预发布 dry-run 显式使用 `--tag next`。
- 本机原生包安装冒烟通过，覆盖版本、后台启动、Web 资源、停止、重启和卸载保留数据。
- 安全审计桌面浏览器验证通过，覆盖脱敏内容定位、详情导航、筛选、翻页与滚动位置恢复，没有浏览器错误或水平溢出。
- Claude Code 2.1.29 在本地模拟上游下的四种配置/模型选择组合通过，未调用真实模型服务。

五平台构建和安装结果以对应提交的 Actions 为准，本地安装测试包只包含 Linux x64 二进制。正式版前还需完成旧版本升级与恢复演练、真实 Codex / Claude 上游接入及 Windows 真实终端 Ctrl+C 验收。模拟上游测试不替代真实服务兼容性验证。

维护者验收清单见 [发布流程](../release-process.md#3-验收候选版)。跨平台和升级验收完成之前，不把此候选版视为稳定版本。

## 恢复旧版本

停止候选版，保留当前数据副本，再安装 `cabletidy@0.2.0` 并恢复升级前的数据及客户端配置备份。旧版启动仍为前台运行。不要假定重装旧版能够撤销配置或审计数据变化；候选版的新审计数据应单独保存，不要求旧版读取。

npm 的 `next` / `latest` 只控制后续默认安装，不会自动升级或降级现有用户。候选版问题应在后续候选版本修复，同一 npm 版本不能覆盖。
